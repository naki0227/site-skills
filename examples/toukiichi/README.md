# 使用例：瀬戸ノ口陶器市の特設ページ

依頼（架空）：岐阜県の架空の町「瀬戸ノ口」で毎年5月に開く陶器市（窯元41軒・2日間）の特設ページ。来場してもらうことが目的。日程・会場マップ・出店する窯元・アクセス・雨天時の案内を1ページで。

- ページ：`index.html`（1枚の HTML、約55KB。外部は Google Fonts の2書体だけ。スクリプト・画像ファイルなし）
- Artifact：https://claude.ai/artifact/TXFnEFtKe1fwRYM5HVcWpc （非公開。見せるには Artifact の共有メニューから共有する）
  - Artifact の中では「カレンダーに入れる」（.ics のダウンロード）が動かない（ビューアーがダウンロードを許さないため）。`index.html` をブラウザで直接開けば動く
- 2026-10-26 に2回作り直した（ユーザーの評価「結構AIっぽい」と、site-skills 0.2.1 の inspect.js・critique.md を受けて）。下の「作り直しで変えたこと」

## 決めた4つ（選ぶスキルの「作る前に決めること」）
| 項目 | 決めたこと |
|---|---|
| ただ1つの行動 | 当日、来場してもらう。最初の画面のボタンはヘッダーの「行き方を調べる」1つだけ。カレンダー（.ics）とメール登録は文字のリンクにした |
| 相手・どこから | 岐阜・愛知に住む器好き。前年に来た人と、Instagram・地元ニュースから来る人。多くはスマホ（仮定） |
| まだ動かない理由 | ① 車で行って停められるか・電車で行けるか（遠い）② 雨だったらどうなるか ③ 41軒もあって、どこを回ればいいかわからない |
| 出せる証拠 | 第38回という続いた年数、窯元41軒の名前と器と値段、昨年 P1 が満車だった時間（10:40〜13:10） |

動かない理由の3つに、1つずつ部品を当てた：①→ 出発地を選ぶ路線図と駐車場の表、② → 最初の画面の赤枠の1行・地図の「雨の日」切り替え・天気ごとの表、③ → 地図と同じ番号の窯元一覧、絞り込み、「回る窯元」（駅から歩く順に並べ直す）。

## 考えの一文と触れる1つ（0.2.1 の `make.md`）
- **考えの一文**：このページでは、陶器市のチラシ（のぼり・番号入りの会場図・2日の時刻表）が、最初の画面になる。競合テスト：近くの別の陶器市の名前を入れると、骨組みは成り立ってしまう。崩しているのは、A1〜E4 の41軒の番号と、雨の日に C・D が体育館へ移る地図、「9:30 登り窯の窯出し（E）」の時刻表という、瀬戸ノ口の中身だけ。
- **触れる1つ**：会場図の番号を押すと、手書きの値札にその窯元・器・値段が出る。「雨の日」に切り替えると、屋内に移る17軒と4軒が薄くなり、移る先が赤枠で出る。最初から E1（共同登窯の窯出し）の値札を出しておく。

## 選んだスキルと理由
- **主：`game-quality-bar`（下位タイプ「イベント・ライブ」）**。選ぶスキルの表の「行く準備をしてもらう」に当たる。`types/event.md` は「日程と会場、当日の案内」を見ることにしていて、依頼の中身（日程・会場・行き方・雨天）がそのまま当たる。
- **副：`lp-quality-bar`（雰囲気「和・上質」）**。game の SKILL.md が「トップ1枚の見た目は lp-quality-bar」としている。陶器（工芸）なので和・上質（とらや）にした。地の白・罫・朱の目印・明朝の見出し・ピルのボタン・動きの値を取った。
- **仕上げ：`site-skills` の `references/ai-tells.md`**（作り直しのときに足された）。
- 迷った点：選ぶスキルの「迷ったとき」には「1ページで完結し、流れが無い → lp」とあり、lp を主にする読み方もできた。日程・地図・行き方という**来場までの流れ**の型が game の event 側にしか無いので、game を主にした。

## スキルで足りなかったこと（自分で決めた部分）
1. **主と副の決め方がぶつかる**：選ぶスキルの表では「行く準備」で game、「迷ったとき」では「1ページで流れが無い → lp」。地元のイベント（陶器市・祭り・マルシェ）の特設ページがどちらか書かれていない。
2. **地図の型が無い**：会場マップの描き方（区画・番号・凡例・SP での大きさ・雨の日の切り替え）は、どのスキルにも実測が無い。全部自分で決めた。実在の陶器市（多治見・瀬戸・益子など）の会場図や、フェスの会場図を解剖すると埋まる。
3. **出店者一覧（数十件）の型が無い**：game の event はラインナップを「文字で組む」までで、40件前後の絞り込み・並べ方・0件は無い。
4. **雨天・中止の案内の型が無い**：屋外イベントで一番気にされる「判断の時刻・天気ごとの段階・変わる場所」が、どのスキルにも無い（Lollapalooza の解剖が開催後だったこともある）。
5. **行き方・駐車場の型が無い**：路線図、駐車場の表、満車の時刻、シャトル。
6. **「回る窯元」（自分の回る順）の型が無い**：フェスの「マイタイムテーブル」に当たる部品。
7. **lp の common.md と和・上質がぶつかる**：common.md の「1セクション1色」「和文太・字間広め」「ずらし影」が、とらやの「無彩色・字間は触らない」と合わない。どちらを優先するかが書かれていない。
8. **地方の催しの見本が無い**：game の event.md は Lollapalooza（英語・大規模フェス）1件だけ。日本の地方の催し（チラシ・のぼりの文化）の見本が無いので、最初の画面の「チラシのように密に組む」は、ai-tells と親のセッションの指摘から自分で決めた。**1回目は lp の和・上質（とらや）のヒーロー「商品1点を中央に」をそのまま当て、写真が無いので絵で埋めた。これが一番 AI っぽく見えた原因**で、スキルに「写真が無いときの、情報が主役のイベントの最初の画面」の見本があれば避けられた。
9. **色の実測が題材に無い**：のぼりの織部の緑は、ai-tells の「題材の現場の色」に従い自分で決めた値で、どのサイトの実測でもない。
10. **書体の出典が無い**：明朝と手書きの書体の選び方（どの書体を、どの部品に）は、スキルに実測が無い。ai-tells の「題材に合えば手書きの書体」から自分で選んだ。
