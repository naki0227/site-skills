# 使用例：十条湯 サウナ予約（架空）

東京・北区の架空の銭湯「十条湯」のサウナを、60分ごとの枠で予約する画面。男女別・定員6名・当日割あり。日付・時間帯・人数を選んで空きを見て、予約の前（内容の確認）までを作った。

- 画面：[`index.html`](index.html)（1枚の HTML・スクリプトの外部読み込みなし。書体だけ Google Fonts から使う字を切り出して読む。写真2枚は `photos/`、出典は `photos/credits.json`）
- Artifact：https://claude.ai/artifact/D3258zrg71QARRVdxwiot7（非公開。見せるには Artifact の共有メニューで共有する）
- 作った日：2026-10-26

## 考えの一文と触れる1つ（site-skills 0.2.1 の make.md）
- **考えの一文**：このページでは、銭湯の**下足札**が、時間を選ぶ部品になる（男女は藍と紅の**のれん**、合計は番台の**伝票**）。競合テスト：近くのサウナ施設やジムの名前を入れると、のれん・下足札・番台が意味を失うので成り立たない。
- **触れる1つ**：男女・人数・日を選ぶと、その日の木札（残り席の●○・満・値段）と伝票の合計・当日割が変わる。

| 項目 | 決めたこと |

## 選んだスキルと理由
- **主：`booking-quality-bar`**。してもらうことが「空きを探して予約してもらう」なので、site-skills の表どおり。
  - 下位タイプは **レンタル・体験**（時間で区切った枠を予約する体験に近い）。ただし見本がまだ無いので、SKILL.md の「近い下位タイプの見本を使う」に従い、**チケット・イベント（DICE）** と **宿（じゃらんnet）** の値を出発点にした。飲食（時間帯の選び方）も近いが、こちらも見本が無い。
- **副：`lp-quality-bar`**、雰囲気は **和・上質（とらや）**。booking は「流れ」のスキルで見た目の値を持たないため。初版は「温かい飲食（びっくりドンキー）」にしたが、紙色の淡いベージュと丸い角が ai-tells.md の「銭湯を北欧カフェの淡色にしない」に当たったので、作り直しで変えた（下の「作り直しで変えたこと」）。とらやは「UIは無彩色、色は商品写真の地に任せる」型で、銭湯では色を「のれん」に任せる形に翻訳できる。混ぜていない（1つだけ）。
- **仕上げ：`site-skills/references/ai-tells.md`**（作り直しのときに追加された、AIっぽさの見直し）。

## スキルで足りなかったこと（自分で決めた部分）
スキルを育てるための手がかりとして、正直に書く。

1. **時間で区切った枠の見本が無い**。レンタル・体験も飲食も「（まだ無い）」で、60分の枠を1日分並べる型・一つの枠の定員の見せ方・受付の締め（開始15分前）は、どのサイトの値も無かった。じゃらんnet の部屋数の段階（10室以上／4〜9／1〜3）を定員6に縮めたのは自分の判断。飲食（席の時間帯予約）か体験（ジム・サウナ・教室）の予約サイトを1つ解剖すると埋まる。
2. **男女別のような「分かれた在庫」を選ばせる型が無い**。どちらを先に聞くか、切り替えたら選んだ枠を外すかは自分で決めた。
3. **割引の見せ方が無い**。DICE は割引コード（ログイン前に開けない、という弱点）だけ。日付で自動に付く割引（当日割）を、日付の帯・一覧・内訳でどう示すかは自分で決めた。
4. **予約前の確認の段の中身**。SKILL.md は「確定の直前まで」が範囲だが、確認の段（規定への同意のチェック、エラーの出し方）の見本は無かった。DICE・じゃらんnet とも、その手前で止まっている。
5. **文字の大きさの段と日本語の本文**。booking には文字の値が無く、lp の温かい飲食（びっくりドンキー）も文字は「丸い英字＋小さな和文」だけで、大きさ・行間の数値が無かった（初版は自分で決めた）。作り直しでは とらや の6段に替えたので、ここは埋まった。手書きの書体（Klee One）を選んだのは自分。
6. **構造化データの型**。viewpoints は Hotel・Restaurant・Event などを挙げるが、銭湯・サウナに合う型は無い。`LocalBusiness`＋`Offer` は自分の判断（実在サイトでの確認なし）。
7. **checklist.md が下位タイプ別に分かれていない**。宿の項目（泊数）とチケットの項目（一覧カードの4列・割引コード）が同じ表に並び、当てはまらない項目を自分で外す必要があった。どの下位タイプの項目かを書いておくと迷わない。
8. **SP で最初の画面に検索を入れる、という決まりが booking に無い**。lp の compare.md（星野リゾート「検索が最初の画面」）で気づいたが、booking 側には値が無かった。

## 13回目の作り直し：主役1つを切り抜き、大きな英字の名前と組む（2026-11-07）
ユーザーの指示「その方向で使用例作り直して」で、最初の画面の作り方の方向を変えた（`aesthetic.md` 先頭「最初の画面の作り方の方向」）。これまでの「静かで本物らしい」形（全面の写真・色の箱・写真に貼ったカード）をやめ、ユーザーが好きと言った9枚のうち **GLASS SHOP** の形（同じ色相の2段の上に、大きなセリフ体の英字を画面いっぱいに組み、その字の間から主役が出てくる）から始めた。

### 切り抜きの手順
- 写真：udono「Noren at a sento by udono in Yoyogi, Tokyo」（Wikimedia Commons、CC BY 2.0）。`photos.js get` の 1920px 指定で取ったが、取れたのは 1280px 版。
- のれんの裾の輪郭を、写真の座標で28点打って囲み（上と左右は写真の端で切れているので、画面の外へ出す前提で端に沿わせた）、OpenCV の grabCut に、囲んだ形を GC_PR_FGD、25px 内側に縮めた形を GC_FGD、14px 外へ広げた帯の外を GC_BGD として渡した（GC_INIT_WITH_MASK、6回）。抜け残り（のれんの奥の暗い格子）は明るさ 55 未満で消した。
- 2色：明るさを、暗い→藍 #1d3f7a、明るい→生成り #fff4e2 に置き換えた（網点にはしていない。布の柄と「ゆ」の字が読めるため）。1600px の WebP（透過、約106KB）にした。「ゆ」の字は店の名前ではない（一般の銭湯の印）ので消していない。
- 出典は画面の右上に「切り抜いて色を変えた。十条湯ののれんではありません」と書いた。洗い場の写真は使わなくなったので、ファイルと出典を外した。

- PC 1440×900・1280×720・スマホ 390×844 を撮って見て、①のれんの「ゆ」が上で切れていたのを、のれんを少し下げ名前を小さくして全部見えるように、②出典とボタンが右下の「使ったスキル」に重なっていたのを、出典を右上（のれんの上に白で）・ボタンを左下の英字の横に、③スマホでボタンと出典が重なっていたのを直した。

## 14回目の作り直し：雰囲気を銭湯の世界から取る（2026-11-07）
