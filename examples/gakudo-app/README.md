# おかえりノート（学童保育の連絡・出欠アプリの製品サイト）

site-skills を試す使用例。架空の依頼「放課後児童クラブの職員と保護者をつなぐ連絡・出欠アプリ『おかえりノート』の製品サイト。職員向けに導入してもらうのが目的。トップ・機能・料金・導入事例」を、1枚の `index.html` で作った（ハッシュでトップ／機能／料金／導入事例の4ページを切り替える）。

- Artifact：https://claude.ai/artifact/NgP37wSMPd9Qa5P4sbJtR8 （非公開。見るには共有が要る）
- 団体名・人名・数字はすべて架空。

## 作る前に決めた4つ
| 項目 | 決めたこと |
|---|---|
| ただ1つの行動 | 30日間の無料お試しを申し込む（支払い情報なし）。副は資料のダウンロード |
| 相手・どこから | 施設長・主任支援員・運営法人の担当者・市区町村の担当課。「学童 出欠 アプリ」の検索と、ほかのクラブからの紹介（仮定） |
| まだ動かない理由 | ①値段（委託料・補助金の範囲で払えるか）②手間（ITに慣れない職員と、保護者全員の登録）③信用（児童の個人情報・アレルギーなどの配慮事項） |
| 出せる証拠 | 実績の数字3つ（時点と数え方つき）、運営形態ごとの事例6件、見積書、セキュリティ・稼働状況、FAQ 11問 |

## 選んだスキルと理由
- **主：`saas-quality-bar`／下位タイプ「業務SaaS」（見本 Backlog）**。してもらうことが「道具を理解して、試す・契約してもらう」で、ページも製品サイト・機能・料金表・導入事例そのもの。題材は社内の業務ツール（出欠・連絡・集金）なので業務SaaS。
- **副：`lp-quality-bar`／雰囲気「ポップ・参加型」（見本 ガールスカウト100周年）**。業務SaaS の見本（Backlog）には配色・文字・動きの実測が無く、見た目を決める材料が要った。向く題材に「学校、NPO」がある。子どもの施設だが、買う人は職員なので、多色は1セクション1色に絞って使った。
- 食い違いは主を優先（例：ボタンは Backlog の「橙の塗り＋橙の枠」を採り、ポップのずらし影はボタンに付けない）。

## スキルで足りなかったこと（自分で決めた部分）
- **業務SaaS に見た目の実測が無い**。Backlog の型は流れ（構成・料金表・事例）だけで、色・文字・余白・動きの値が無い。副の lp の「ポップ」を足したが、ポップは周年サイトの値で、B2B の製品サイトの見た目としてはずれる。業務SaaS の見本に配色・文字の実測があれば副は要らなかった。
- **lp の「ポップ・参加型」の `types/pop.md` は1行だけ**で、値は `common.md`（ガールスカウト）にある。ベース色 `#009a59` は白地で 3.4:1 と本文に使えず、暗くする値は自分で決めた。登場の ±100px も 390px ではみ出すので ±40px にした。
- **状態（空・エラー・送信中・完了）の型がどちらのスキルにも無い**。フォームのエラー文、0件の事例の表示、送信中の表示は自分で決めた。saas の checklist に状態の項目が無い。
- **フォームの中身**（お試しの項目数、必須の付け方）は Backlog の申込フォームが robots.txt で未確認とあり、出発点が無かった。クラブ名・運営形態・児童数・名前・メールの5項目は自分で決めた。
- **製品画面を画像なしで見せる型**：Backlog は実画面のキャプチャ。DOM のモックは開発者向けの Resend の型から借りた。業務SaaS 側にも DOM モックの値（大きさ・情報量）があると良い。
- **「一日の流れ」のタイムラインとページの切り替え**（1枚で4ページ）はスキルに無い構成。前後比較（「これまで：…」）をどこに置くかの型も無い。
- **料金の決め方**：児童数で選ぶスライダー（Resend）と、問いに答える診断（Backlog）を両方置いたが、どちらを主にするかの判断材料がスキルに無い。
- **ファイルを渡す部品**：見積書のダウンロードは、Artifact の画面ではファイルを保存できない。ページの中に見積書の文面を出して、コピーできるようにした（スキルの外の、公開先の事情）。
- **題材固有の事実**（支援の単位はおおむね40人以下、など）はスキルの外。一般に知られた制度として使った。
- 個人向けアプリ（保護者のスマホ）側の型（`types/app.md`）はまだ空で、保護者向けの見せ方は参考にできなかった。
