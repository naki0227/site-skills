# 使用例：町工場の採用サイト（河内精機）

架空の依頼「大阪府東大阪市の町工場・河内精機（創業1965年、従業員38名、精密な金属部品の切削）の採用サイト。若手の機械オペレーターを採りたい」を、site-skills の手順どおりに1枚の HTML にしたもの。
2026-10-26 にユーザーの評価（「結構AIっぽい」）を受け、`site-skills/references/ai-tells.md` を当てて作り直した。さらに site-skills 0.2.1 の手順（`make.md`・`scripts/inspect.js`・`critique.md`）でもう一度直した（下の「作り直しで変えたこと」）。

- **考えの一文**：このページでは、事務所前の見学日のホワイトボードが、最初の画面の申し込みの入口になる（ほかに、検査記録票と作業日報が仕事の章の主役になる）。
- **触れる1つ**：ホワイトボードの日を押すと、申し込みフォームの見学日と申し込む内容が入る（満員の日は赤線で消してあり、押せない）。

- ファイル：`index.html`（約 71KB。スクリプトの依存なし。書体だけ Google Fonts の Klee One を読む。写真は「写真の枠」、部品の図だけ SVG）
- Artifact：https://claude.ai/artifact/WZVX1SbegJjs3XMWmoqeA7
- 会社・人物・電話番号・求人番号はすべて架空（ページのフッターにも書いた）。

## 作る前に決めた4つ（site-skills）
- **ただ1つの行動**：工場見学の申し込み（同じフォームで「見学してから応募」「見学なしで応募」も選べる）。
- **相手と来た道**：東大阪・八尾あたりの10代後半〜20代。工業高校生、フリーター、別の仕事からの転職。ハローワークの求人票・学校の進路指導・Instagram から来る。
- **まだ動かない理由3つ**：①町工場は暑い・汚い・きついという印象 ②図面も機械もわからない不安 ③給料・休み・残業が見えない。
- **出せる証拠**：給料・残業 11.4時間・年間休日 117日・定着 9人中8人の実数、先輩4人の声（前職つき）、検査記録票と作業日報、空調で室温 31.2℃→27.4℃。

1文にすると：「東大阪の10代後半〜20代に、まず工場見学をフォームから申し込んでもらう採用ページ」。

## 選んだスキルと理由
- **主：`corporate-quality-bar`（下位タイプ：採用サイト）**。してもらうことが「会社を信頼して、採用に進んでもらう」なので、選ぶスキルの表どおり。採用サイト・中小企業の見本はまだ無いので、近い見本の LayerX（startup.md）と Valmont（enterprise.md）の型を使った。
- **副：`lp-quality-bar`**。1回目は雰囲気「ミニマル・ハードウェア（teenage engineering）」を使ったが、作り直しで外した。黒地・極細の文字・流れる帯は開発ツールやガジェットの型で、町工場に合わなかった（ai-tells「雰囲気を題材に合わせる」）。lp の雰囲気の表に工場・ものづくりは無いので、型は使わず rules（ホバー・動き・軽さ）だけ当てた。
- **仕上げ：`site-skills/references/ai-tells.md`**。全項目を当てた（下の表）。

## 確かめたこと（Playwright、1440px と 390px）
- 最初の画面と全体を撮って目で見た。作り直しで見つけて直したもの：①スマホで記録票の表（最小幅 560px）がグリッドの列を押し広げ、ページ全体が 614px に（列を minmax(0,1fr) に） ②スマホで主ボタンの小さな文字が折り返して崩れる（縦に積む） ③スマホでは記録票が下にあるのに本文が「右の記録票」と書いていた。
- 横スクロール：なし（scrollWidth＝画面の幅。表は自分の枠の中だけで横に動く）。
- コンソールのエラー・ページのエラー：0。
- 操作：ホワイトボードの日を押す → フォームの日付と申し込む内容が入る、部品のタブ（クリックと←→キー）、人の「話を読む」、給料の切り替え、フォーム（空で送る→エラーの一覧と欄の赤枠 → 入れて確認 → 送る（送信中の表示）→ 完了と受付番号 → もう一度）、使ったスキル（Esc で閉じる）、SPメニュー。すべて動いた。

## スキルで足りなかったこと（自分で決めた部分）
スキルを育てるための手がかり。ここに書いたことは、どのサイトの値でもなく、自分で決めた。

1. **採用サイトの見本が無い**（corporate の recruit.md・sme-local.md が空）。社員の声の見せ方、募集要項の項目と並べ方、見学から入る流れ、給料の切り替え、見学日の選び方は、どの実在サイトの値でもない。中小の製造業の採用サイトを1つ解剖すると、この例の大半が出典つきに置き換えられる。
2. **募集要項・応募フォームの型が無い**。欄の数と必須の数、確認画面、エラーの出し方は corporate に無い。LayerX の「入力→確認→完了・入力欄8つ」だけを足場にし、エラーの一覧・欄の赤枠・残りの必須の数・文字数は自分で決めた。
3. **見た目の値の多くが英語のサイトの値**。Valmont の h1 76.5px・行間 1.05・字間 -0.03em は欧文用で、和文では行が重なる。日本語の採用・コーポレートサイトの文字の値が欲しい。
4. **lp の雰囲気の表に「工場・ものづくり・現場」が無い**。1回目はミニマル・ハードウェアを借りて AI っぽくなった。作り直しの色（作業着・床・安全表示・ボード・記録票）と書体の組み合わせは、すべて実在サイトの値でなく自分の判断。町工場や建設・設備会社の採用サイトを解剖して雰囲気を1つ足すと、この部分が出典つきになる。
5. **ai-tells.md は「やめること」が中心で、「代わりに何をするか」の型が少ない**。ホワイトボードや記録票のような「題材でしか成り立たない部品」の作り方（どの紙・道具を画面に持ってくるか、どこまで本物に寄せるか）は自分で決めた。実在サイトでそうしている例があれば、型として足せる。
6. **inspect.js は最初の3画面だけを数える**。罫と枠を外したのは全体だが、4画面目より下（人・給料・会社・フォーム）の線の量は測っていない。
7. **写真の枠が並ぶと「灰色の箱」に見える**。ai-tells は写真の枠を勧め、critique は灰色の箱を中身の上限（5まで）にしている。撮るべき写真を書いた枠と、ダミーの灰色の箱の見分け方が無い。
8. **手書きの書体の読み方**。0.2.1 の ai-tells は Google Fonts の `text=` で使う字だけ読むよう勧めている。この例は見学日を JS で作るので字を前もって決めにくく、`unicode-range` の分割（使う範囲だけ読まれる）に任せたまま。`text=` には変えていない。
9. **架空の会社の扱い**（電話番号・求人番号を架空と書く、送信しない旨を完了画面に出す）はスキルの範囲外で、自分で決めた。
