# 横断ルール：メディアのサイトをまたいで効いていること

2つ以上のサイトで同じ結果になったことだけを、番号つきで書く。1サイトだけの発見は `types/<slug>.md` に置く。
書くときは（〇〇と△△で確認）のように、元になったサイトを添える。

1. 長い記事でも目次を付けないサイトがある。高さ1万px超の記事は目次と「いま読む節」の印を付ける（メルカリエンジニアリング：高さ 15,659px、ProPublica：高さ 21,446px、北欧、暮らしの道具店：高さ 16,318px、King Arthur Baking：レシピ 10,852px・手順17、4サイトとも本文の目次無し）。
2. 画像の width/height が抜けると、記事の途中で寸法が決まらず、元画像を引き伸ばしたり本文を押し下げたりする。全画像に寸法を付ける（メルカリエンジニアリング：アイキャッチ無しで PC CLS 0.064、ProPublica：長い記事の写真が元 300px を 810px に拡大、北欧、暮らしの道具店：本文の写真13枚に寸法無しで PC CLS 0.0642、King Arthur Baking：一覧のカードの写真 323×218 と自社の帯に寸法無し）。
3. 記事の終わりに「次の1本」へ進む大きな導線を置く。2サイトとも関連は小さな一覧だけで、著者紹介も無かった（メルカリエンジニアリング：関連3件の帯、ProPublica：Read More 枠・More in 分類6本・Most Read 9本）。
4. 一覧の2ページ目以降に URL を持たせる（メルカリエンジニアリング：「もっと見る」で増やした分に URL 無し、ProPublica：連載の川24本で終わり、次のページへのリンクが見つからない、King Arthur Baking：ページ送りが href の無い button で、?page=2 は history で書くだけ）。守れている見本は北欧、暮らしの道具店（「次へ」で /note/page/2・rel="next"）。
5. 記事に Article の JSON-LD（公開日・更新日・書き手）を入れる。読みもののサイトでも 0件のことがある（メルカリエンジニアリング：JSON-LD 無し、北欧、暮らしの道具店：5ページとも 0件・レシピ記事にも Recipe 無し）。
6. ホバーの変化は `@media (hover:hover)` で囲む。囲まないサイトが続いた（ProPublica：:hover 159か所に 0、北欧、暮らしの道具店：:hover 166か所に 0、King Arthur Baking：:hover 516か所に 0）。
7. 日本語の本文は端末の書体で組み、Web フォントは読まないか約物だけにする（メルカリエンジニアリング：Web フォント無しで游ゴシック体、北欧、暮らしの道具店：かっこ18字の YakuHanJPs だけで 6KB）。
8. 記事の重さは、解析・広告のタグを外した値と全部込みの値の両方で測る。タグの分を外して測ると見落とす（ProPublica：記事 148ホスト・626リクエスト、北欧、暮らしの道具店：記事 PC 5.25MB → 全部込み 6.30MB、自社ドメインの /scripts/ から GTM と gtag 2.28MB、King Arthur Baking：記事 PC 8.67MB → 全部込み 13.28MB・44ホスト、GTM だけで 3.47MB）。
