1. 長い記事でも目次を付けないサイトがある。高さ1万px超の記事は目次と「いま読む節」の印を付ける（メルカリエンジニアリング：高さ 15,659px、ProPublica：高さ 21,446px、北欧、暮らしの道具店：高さ 16,318px、King Arthur Baking：レシピ 10,852px・手順17、LINEヤフー Tech Blog：PC 14,750px・SP 21,153px、Quanta Magazine：PC 12,051px・SP 16,623px、白ごはん.com：SP 11,780px、The Markup：調べ方の記事 19,491px・h2 5・h3 11、Grist：長い調査記事 PC 38,482px・SP 53,769px・h2 4・見出しの id 無し、9サイトとも本文の目次無し。The Markup は見出しの id が読める言葉なのに目次が無い。LINEヤフー Tech Blog は CSS に目次の箱があるのに40本で使用 0）。守れている見本は DeNA Engineering（見出しの id を日本語のまま持ち、右 280px・sticky top 90px の目次で、IntersectionObserver がいまの節を青の太字にする。long 25,036px でも目次は 665px で画面に収まる。ただし監視の線〔上から 90px〕が押したときの飛び先〔100px〕より上で、押した節の1つ前が太字のまま残る。線は飛び先より下に置く）。レシピでは、目次の代わりに工程を2組・8行に縮めた「大まかな流れ」を開けるようにした見本がある（白ごはん.com：PC はモーダル、SP は右下の丸いボタンからシート）。YAMAP MAGAZINE は記事の頭に目次（#fafafa の箱・728×235）を置くが、項目は button で見出しに id が無く（long の h2・h3 11個とも）、入るのは h2 だけ・押すと 0ms で飛び URL も変わらない・固定もいまの節も無い。目次はリンクと id で作る。Great British Chefs でも：レシピ long PC 10,799px・SP 15,224px・手順18で目次も「いまの手順」も無く、ページ内の飛び先は JUMP TO RECIPE（約700ms で材料の箱へ）だけ（2026-11-04）。
2. 画像の width/height が抜けると、記事の途中で寸法が決まらず、元画像を引き伸ばしたり本文を押し下げたりする。全画像に寸法を付ける（メルカリエンジニアリング：アイキャッチ無しで PC CLS 0.064、ProPublica：長い記事の写真が元 300px を 810px に拡大、北欧、暮らしの道具店：本文の写真13枚に寸法無しで PC CLS 0.0642、King Arthur Baking：一覧のカードの写真 323×218 と自社の帯に寸法無し、LINEヤフー Tech Blog：本文の図が width="1000" height="auto"。height="auto" は寸法にならない、The Markup：5ページとも width/height・srcset・lazy 無しで、360px 表示の写真が 574KB、DeNA Engineering：本文の図も一覧の写真も width/height 無し・1200×628 の PNG を 320px で、Grist：記事の画像 57枚中 45 に寸法無し、トップ SP の CLS 0.3450 は書き手の行）。守れている見本は LINEヤフー Tech Blog の一覧（写真を padding-bottom 52.6316% の箱に入れ、CLS PC 0.0012・SP 0）と DeNA Engineering の一覧（aspect-ratio 40/21・object-fit cover で CLS 0.0005〜0.0022）。
3. 記事の終わりに「次の1本」へ進む大きな導線を置く。関連は小さな一覧だけのサイトが続いた（メルカリエンジニアリング：関連3件の帯、ProPublica：Read More 枠・More in 分類6本・Most Read 9本、LINEヤフー Tech Blog：Related Post 3本だけ、The Markup：You just read と Credits の後に The Latest 3枚だけ、DeNA Engineering：シェアの面の後に Related Articles 3本〔タグで選び、2019〜2022年の記事〕だけで次の記事も著者紹介も無い。著者紹介は LINEヤフー Tech Blog と The Markup〔顔 58px・肩書・編集者2人〕にある）。守れている見本は Quanta Magazine（全幅の NEXT ARTICLE：PC 400px・SP 323px、題は白の 40px 級。その前に同じ分類の3本）と Grist（本文と同じ 706px の幅に Next Article：写真 706×397・題 50px／60px、SP 32px。その前にニュースレター2枚、後に同じ分類と最新）。YAMAP MAGAZINE も終わりは関連3本（372×445）と横組みのおすすめ4本で、大きな次の1本は無い。スポンサー記事の終わりには関連もおすすめも無い。Great British Chefs でも：終わりはニュースレター → コメント（ログイン）→ You may also like の混ぜ組みで、次の1本の大きな導線は無い（2026-11-04）。
4. 一覧の2ページ目以降に URL を持たせる（メルカリエンジニアリング：「もっと見る」で増やした分に URL 無し、ProPublica：連載の川24本で終わり、次のページへのリンクが見つからない、King Arthur Baking：ページ送りが href の無い button で、?page=2 は history で書くだけ）。守れている見本は北欧、暮らしの道具店（「次へ」で /note/page/2・rel="next"）。LINEヤフー Tech Blog は番号に /page/2 の URL があるが、前後の矢印がいつも aria-disabled・href="#"。Quanta Magazine は /mathematics/page/2・rel="next" があるが、SP で番号を隠して NEXT だけにする。Grist は /energy/page/2/・rel="next" に加えて、SP で「1 of 196」と今の位置を残す。YAMAP MAGAZINE は一覧もトップも「もっと見る」で 17 → 27本に増やし、URL は /magazine/categories/2 のまま（押した後の PC の CLS 0.4361）。Great British Chefs でも：一覧の「Load more」が href の無い div で、ページ番号も rel="next" も無い（2026-11-04）。
5. 記事に Article の JSON-LD（公開日・更新日・書き手）を入れる。読みもののサイトでも 0件のことがある（メルカリエンジニアリング：JSON-LD 無し、北欧、暮らしの道具店：5ページとも 0件・レシピ記事にも Recipe 無し、Quanta Magazine：記事も WebPage で、日付と author を WebPage に載せる、白ごはん.com：4ページとも 0件で、microdata の Recipe は name・image・description だけ、The Markup：ニュースなのに5ページとも 0件で meta の article:published_time だけ、DeNA Engineering：4ページとも 0件・html に lang も無い）。置くときは1組にまとめる（Grist：Yoast の Article と別の NewsArticle を記事ごとに二重に）。YAMAP MAGAZINE：4ページとも 0件で、画面には投稿日・更新日があるのに time も無く、記事に meta description も無い。
6. ホバーの変化は `@media (hover:hover)` で囲む。囲まないサイトが続いた（ProPublica：:hover 159か所に 0、北欧、暮らしの道具店：:hover 166か所に 0、King Arthur Baking：:hover 516か所に 0、LINEヤフー Tech Blog：:hover 26か所に 0、Quanta Magazine：:hover 136か所に 2、白ごはん.com：:hover PC 25か所に 0、The Markup：:hover 104か所に 4、DeNA Engineering：:hover 20か所に 0、Grist：:hover 191か所に 0。ただし本文のリンクと目次の2つは (pointer:fine) の中に入れ、(pointer:coarse) には :active を置く）。Great British Chefs でも：:hover 62か所のうち (hover:hover) の中は11（2026-11-04）。
7. 日本語の本文は端末の書体で組み、Web フォントは読まないか約物だけにする（メルカリエンジニアリング：Web フォント無しで游ゴシック体、北欧、暮らしの道具店：かっこ18字の YakuHanJPs だけで 6KB）。日本語の Web フォントを本文まで使うと記事1本で 1MB を超える（LINEヤフー Tech Blog：LINE Seed JP の CSS 224KB・@font-face 278個＋woff2 1.04MB、DeNA Engineering：Noto Sans JP で記事 884KB・長い記事 1,046KB、Google Fonts の CSS 244KB）。YAMAP MAGAZINE も Helvetica Neue → Arial → ヒラギノ角ゴ → メイリオの端末の書体だけで、@font-face 0・フォントの通信 0。
8. 記事の重さは、解析・広告のタグを外した値と全部込みの値の両方で測る。タグの分を外して測ると見落とす（ProPublica：記事 148ホスト・626リクエスト、北欧、暮らしの道具店：記事 PC 5.25MB → 全部込み 6.30MB、自社ドメインの /scripts/ から GTM と gtag 2.28MB、King Arthur Baking：記事 PC 8.67MB → 全部込み 13.28MB・44ホスト、GTM だけで 3.47MB、LINEヤフー Tech Blog：記事 PC 4.37MB → 全部込み 4.96MB・9ホスト、Quanta Magazine：記事 PC 14.14MB → 全部込み 15.43MB・19ホスト、白ごはん.com：記事 PC は48ホスト・広告の配信元だけで AdSense・GPT・Yahoo・fundit・i-mobile・logly・criteo ほか）。広告もタグマネージャーも置かない見本は The Markup（記事 PC 2.38MB・17件・3ホスト、外は解析 27KB だけ）。YAMAP MAGAZINE：記事 PC 3.10MB → 下まで読んだ全部込み 5.84MB・15ホスト、うち GTM 1,193KB。
9. SP で表やコードを横に送るときは、はみ出したときだけ続きの手がかりを出す。右端で切れるだけのサイトが続いた（メルカリエンジニアリング：表 470px を 348px で、LINEヤフー Tech Blog：表 490px を 350px で、DeNA Engineering：長い記事のコード13本すべてが SP で横送り、どれも手がかり無し）。

11. 動画は押すまで、または見える範囲に来るまで読まない。最初から読む埋め込み・自動再生が、ページの重さの半分を超えた（King Arthur Baking：トップの YouTube 3,683KB、Quanta Magazine：トップの YouTube 4本で 16,483KB・主役の mp4 8,746KB、記事 SP の自動再生 mp4 2本で 15,987KB、白ごはん.com：記事の YouTube の埋め込みを最初から読み、転送 約980KB・展開 3.5MB、The Markup：調べ方の記事で Datawrapper の iframe 13枚と動画9本を読み 19.82MB、下まで送って 43.10MB）。図表の iframe も同じで、見える範囲に来るまで読まない。自動再生を残すなら prefers-reduced-motion で止める（Quanta Magazine は 0か所）。Great British Chefs でも：トップの mp4 3,729KB を autoplay・loop・controls 無しで流し、PC のトップ 9.20MB の4割（2026-11-04）。
