# 横断ルール：SaaSのサイトをまたいで効いていること

2つ以上のサイトで同じ結果になったことだけを、番号つきで書く。1サイトだけの発見は `types/<slug>.md` に置く。
書くときは（〇〇と△△で確認）のように、元になったサイトを添える。

1. 料金ページの下に FAQ を10問以上置き、料金・上限・支払いの疑問をそこで答える（Backlog 10問、Resend 15問）。Resend は FAQPage の構造化データも付け、Backlog は付けていない。Nani翻訳は料金ページに FAQ を置かず、上限は ? の吹き出し、支払いはヘルプの3問に分けている。Todoist も料金ページに FAQ を置かず、ヘルプの記事1本へのリンクだけ（個人向けの2サイトは、どちらも料金の FAQ をヘルプに置く）。microCMS も料金ページに FAQ を置かず「ご契約に関するよくある質問はこちら」でヘルプへ。代わりに比較表の下に注 ※1〜※8（超過時の API 停止・トライアルは1サービス1回など）を置く。 TimeTree の料金ページは FAQ 4問で、3問が解約、1つが注意事項6行（ストアで払うアプリの自動更新・返金）。
2. 比較表は5〜8区分に分け、区分ごとに見出しを付ける（Backlog 5区分35行、Resend 6区分45行、Todoist 5区分39行、microCMS 8区分46行）。行が40を超えると、Backlog の SP・microCMS は `<details>` で区分を開閉できるようにしている。Granola は5区分35行で開閉なし（11・3・8・11・2行）。
3. 契約の入口の文言は、プランごとに変えず1つにそろえる（Backlog は全カード同じトライアル、Resend は全カードのボタンが「Get started」で /signup、Todoist は有料2枚とトップ・ナビが「無料で開始する」で /auth/signup、無料のカードだけ「始める」、microCMS は3枚が「無料で始める」で app.microcms.io/signup、Enterprise だけ「お問い合わせ」。ただし microCMS はヘッダー・トップでは「無料ではじめる」とかなにしていて、文言が2つある）。Granola はトップ・Chat・料金の主ボタンが全部 notes.granola.ai/download（Basic・Business「Download for Mac」、Enterprise「Sign-up in app」）で、行き先は1つ。 TimeTree は文言が4通り（ヘッダー「無料ではじめる」、SP のメニュー「無料でTimeTreeをはじめる」、事例の「TimeTreeをダウンロードする」、ストアのバッジ）で、行き先も /signup・ストア・onelink に分かれる。
4. 最初の画面の行動は2つにし、主は「試す」、副は「読む」（資料・ドキュメント）にして、副を見た目で一段弱くする（Backlog は橙の塗りと橙の枠、Resend は枠＋面のボタンと枠なしの文字）。個人向けアプリの Todoist は「無料で開始する」1つだけで副を置かない（業務SaaS・開発者向けの型）。microCMS の副は資料ではなく「ビジネス職向けページ」（読み手を役割で分ける入口、枠のボタン）。AIプロダクトの Granola も最初の画面は「Download for free」1つで、相談はヘッダーの「Talk to sales」だけ（Todoist と同じく、アプリを入れて試す製品は行動を1つにしている）。 TimeTree（個人向け）も行動はヘッダーの「無料ではじめる」とストアのバッジだけで副を置かない。ただし PC ではバッジが y=1,121px で最初の画面の外。
5. 年払いの割引は、切り替えの部品の中か横に率で書く（Backlog はラベルに「(5%オフ)」、Nani翻訳はタブの中に青い札「-20%」、Todoist は切り替えの横に緑の札「約20%オフ」）。3つとも年払いのときだけ価格の横に年額を出す（Backlog は年額の行、Nani翻訳は「￥12,000 年払い」、Todoist は「$60 年払い」）。個人向けの2つ（Nani翻訳・Todoist）は、初めから年払いを選んでいる。年払いが無いサイトは Resend（FAQ に「月払いのみ」と書く）と Granola（どこにも書かない）。 TimeTree は切り替えの部品を置かず、本文の一文で「年額3,000円（初月無料、2ヶ月分割引）」と月数で書く（実際は 16.7%）。
6. 稼働状況のページを別ドメインに持ち、フッターからつなぐ（Backlog は status.nulab.com、Nani翻訳は「障害情報」→ status.nani.now、Todoist はフッターとヘルプの「システム ステータス」→ status.todoist.net）。 TimeTree は別ドメインを持たず、ニュースルームの分類「メンテナンス・障害情報」に載せる。
7. 相談・チャットのウィジェットを全ページで読み込み、どのページでも一番重いファイルにしている（Backlog・コドモンは商談予約の immedio main.js 2,037KB、microCMS は PC だけ HubSpot の会話 visitor.js 1,404KB＋CSS 537KB ほか 約 2.5MB で、機能ページの PC の 69%）。真似ない：右下のボタンは自前の小さな部品にし、押したときに本体を読む。
8. 実績の数字には、時点と数え方を添える（Backlog「2026年6月末」と数え方の注記、コドモン「2026年10月1日時点」と※の数え方・調査元）。microCMS の「ご利用企業数17,000社以上・継続率99%」には時点も数え方も無く、何を数えたのか（無料を含むか）がわからない。Granola の事例の数字（Vanta「260+ hours annually per user」「69%」「61%」）にも時点と数え方が無い。 TimeTree は歩いた5ページに実績の数字を1つも置かない（事例も数字0）。
9. 検索の0件は、見出しと一言だけで終わっていて、言い換えの例・よく読まれる記事・問い合わせへの道を出さない（コドモンのヘルプは「0件」の見出しだけ、Todoist のヘルプは「他のキーワードをお試しください。」と挿絵だけ、microCMS の事例の絞り込みは「0件」と「絞り込み条件（リセット）」だけで、リセットは span）。真似ない：0件には言い換えの例と、よく読まれる記事2〜3件と、問い合わせへの道を置く。
10. 流れ続ける帯を、`prefers-reduced-motion: reduce` でも止めない（Nani翻訳の声の帯は 48s のまま、Todoist の数字の帯は 30s → 180s に遅くするだけ、Granola の Chat の札の帯 30s とロゴの帯 90s も reduce で running のまま）。どちらも止めるボタンが無い。真似ない：reduce では止めて横に並べ、止めるボタンを付ける。 反例：TimeTree の Swiper のカルーセル（3000ms）は、reduce では送らず1枚目のまま。
11. 事例の詳細は、問答の本文の前に「導入前の課題」「導入後の効果」を箇条書きで置く（Backlog は h1 に成果の数字＋課題・効果の箇条書き、microCMS は課題3行・効果2行のあとに目次）。読み手は箇条書きだけで自分ごとかを決め、本文は確かめたい人が読む。
12. 「試す」の直前か中に、クレジットカード（支払い情報）が要らないことを書く（Backlog はボタンの中に「支払い情報の入力不要」、microCMS はボタンの直前に「＼ クレジットカードの登録不要 ／」と料金の Hobby のカード）。Todoist・Granola はどのページにも書いていない。 TimeTree も書いていない（個人向けアプリの2つはどちらも書かない）。
13. 製品画面の動き（動画・DOM のモック・スクロールの演出）を、`prefers-reduced-motion: reduce` でも止めない（Nani翻訳は Motion を `reducedMotion:"never"`、Todoist は製品の動画を reduce でも再生、Granola は DOM のモックの約8.6秒の1巡と、`animation-timeline` の scroll／view の12個が reduce でも動く）。真似ない：reduce では結果の画面で止め、scroll timeline は `@media (prefers-reduced-motion: no-preference)` の中でだけ付け、モックに止めるボタンを置く。
14. 比較表のプラン名の行を sticky にして、長い表のどこでも列の名前が読めるようにする（Todoist top:72px、Granola の thead top 64px・SP 56px）。Granola は SP で行の名前を全幅に・値3つを下の3列に組み替え、表ごとの横スクロールにしない（microCMS の SP は 1024px の横スクロールで行の名前が流れる）。
15. 製品画面の画像・動画を言語ごとに作り直し、その言語の予定・タスクで埋める（Todoist は `/product-ui/sequences/ja/` の動画に「ヨガ 30分間」「歯科の予約」、TimeTree は `hero_ja.png` などファイル名に `_ja` を付け「大掃除」「年越しそば」「小学校始業式」）。訳した文の横に英語の画面を置かない。
16. 個人向けアプリの製品サイトは、構造化データを置かない（Todoist 0、TimeTree は5ページとも0）。AIプロダクトの Granola は AggregateRating を構造化データにだけ書く。作るときは SoftwareApplication（offers に価格）と FAQPage を、画面に出ている値だけで付ける。
