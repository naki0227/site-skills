# SaaS品質基準

目標は、「何をする道具か→自分の仕事がどう良くなるか→いくらか→今すぐ試せる」が、営業に聞かなくてもわかる水準。
見た目をコピーするのではなく、解剖した**流れと判断**を、作るものに合わせて翻訳する。

## 使い方
1. 下の表で、作るものに一番近い下位タイプを選ぶ。
   - 最初の画面（ファーストビュー）は、型の数値より先に `references/first-screen.md`（ユーザーに本物か作例か当ててもらった15回の結果：雰囲気を1つの言葉で決めて写真・字・構図をそろえる、キャッチコピーを文にしない、など）に合わせる。
2. `references/viewpoints.md` を読み、作る画面ごとに、そこに並ぶ問いへの答えを先に決める。
3. 選んだ下位タイプの `references/types/<slug>.md` を読み、見本の実測値を出発点にする。見本がまだ無い下位タイプは、近い下位タイプの見本を使う。
4. `references/rules.md`（サイトをまたいで効いていること）に反していないか確かめながら作る。
5. 仕上げに `references/checklist.md` を全部確かめる。

## 下位タイプを選ぶ
| 下位タイプ | 向く題材 | 見本（解剖したサイト） | ファイル |
|---|---|---|---|
| 開発者向け | API、開発ツール、インフラ、ヘッドレスCMS、ノーコードのWeb制作、データベースの基盤、配信と AI の基盤、サーバー監視、使った秒で払うデプロイ基盤、料率で払う決済 API | Resend、microCMS、Studio、Supabase、Vercel、Mackerel、Railway、PAY.JP | `types/devtools.md` |
| 業務SaaS | 営業・人事・会計・社内ツール・保育や学童などの現場・製品開発の課題管理・CRM・問い合わせ（サポート）の受付・法人カードと経費の精算・営業のデータ集めと自動化（使用量の2つの量で払う）・顧客の声を集めて AI に渡す（基盤＋件数のクレジット）・チームとエージェントの共有ワークスペース（基本と AI の2つの箱） | Backlog、コドモン、Linear、Attio、Plain、Ramp、Clay、Dovetail、Notion | `types/business.md` |
| AIプロダクト | 生成AI・AIを中心にした製品、会議や記録の AI（議事録）、コーディングのエージェント、動画・画像の生成（クレジット課金）、法人の議事録（録った時間で払う）、AI電話の受付（電話をかけて試す） | Nani翻訳、Granola、Cursor、Rimo、Notta、Runway、LINE WORKS AiNote、アイブリー | `types/ai.md` |
| 個人向けアプリ | スマホ・PC のアプリ、個人で使う道具、共有カレンダー、家計簿・資産管理、プリペイドカードと家計簿（ふたり・子どもと使う）、家族で写真を共有するアルバム（ストアと Web で値段が違う）、Mac のランチャー（無料＋AI の段） | Todoist、TimeTree、マネーフォワード ME、Moneytree、くふう Zaim、ワンバンク、みてね、Raycast | `types/app.md` |

## このスキルの範囲
- 製品サイトの機能・料金・事例・試すまでの導線。製品そのもの（管理画面）は対象外。トップの見た目と雰囲気は `lp-quality-bar`（テック・SaaS／テック・ダーク）。
- どのスキルを使うか迷ったら `site-skills` で選ぶ。
