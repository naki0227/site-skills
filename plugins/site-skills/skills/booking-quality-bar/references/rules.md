# 横断ルール：予約のサイトをまたいで効いていること

2つ以上のサイトで同じ結果になったことだけを、番号つきで書く。1サイトだけの発見は `types/<slug>.md` に置く。
書くときは（〇〇と△△で確認）のように、元になったサイトを添える。

1. 払い戻し・キャンセルの条件は、最初の予約ボタンより下に置かれがちで、実測すると買う枠から遠い（じゃらんnet：ボタン y=683 に対し規定 y=3070／DICE：枠 y=547 に対し条件 y=1034、SP も同様／TableCheck：予約フォームの主なプランに規定が無く、一部のプラン説明の※1行と、ページ最後の「関連する規約とポリシー」だけ／Othership：時間割の行と枠の詳細に無く、規約ページと店ページの料金カードの「12 HOUR LATE CANCEL WINDOW」だけ／星野リゾート：プランの中にあるが、閉じた10pxの「キャンセル規定 ∨」（70×25）の中で、開くと「カートに入れる」の上に面が重なる／Shakespeare's Globe：公演ページに返券・払い戻しが無く、48時間前までのクレジット返券と1枚 £2〜£3 の手数料はチケットの規約のページだけ／チームラボプラネッツ：入場日時・時間枠・枚数の3画面に「キャンセル」「返金」「変更」が0語。返金不可と「入場の2時間前まで・3回」の日時変更は、展示ページの 22,675px 下の FAQ とヘルプだけ／Resy：店ページに無く、枠を押したパネルで初めて「before Wed, Nov. 11 at 5:30pm」と出る。パネルの中ではボタン y=886 より上の y=246 だが、規定の無い店は行ごと消え、FAQ は「確認メールを見て」）。作るときは、ボタンと同じ枠の中か、すぐ下の1行に入れる。
2. 予約サイトの1ページは重い。JS が最大の荷物になる（じゃらんnet 2.78〜7.60MB／DICE 8.33〜14.42MB／TableCheck 一覧・店 13.94〜15.60MB／Othership 6.13〜12.89MB、どれも PC。TableCheck は3ページとも JS 1本 10.04MB（転送 2.38MB）。DICE は公演ページでもヘルプでも Stripe 1.1MB・reCAPTCHA 約840KB×3 を読む。Othership は時間割の無い規約ページでも予約エンジンの /js 322KB を読む／星野リゾート 3.83〜19.88MB、規定のページでも JS 3.1MB。宿ページは動画 6.73MB と Google Fonts の CSS 2.1MB が JS と並ぶ／Shakespeare's Globe 3.65〜13.30MB、JS は全ページ 1.44MB 前後で、いちばん重いのは写真（ツアーの JPEG 8.9MB・トップの GIF 2,985KB）。クッキーの帯 OneTrust 850KB は規約の入口でも読む／チームラボプラネッツ：入場日時の画面は 0.84MB と軽いが、枠を押した先の枚数の画面で reCAPTCHA 839KB×3、展示ページは動画で PC 103.84MB／Resy 19.48〜23.94MB、5ページとも JS 11.5MB・全都市の JSON 3.39MB・Stripe 1.15MB・reCAPTCHA 836KB を FAQ でも読む）。予約エンジン・決済・ボット対策のスクリプトは、選択を始めるまで読まない形を目指す。
3. 空きの記号（○・▲・×）の凡例は、記号のそばに出ていない（じゃらんnet PC：凡例は「?」の中／TableCheck の詳細：○・×・定休日に凡例なし／星野リゾート：凡例は2か月のカレンダーの下／チームラボプラネッツ：PC は凡例がカレンダーの下で、ひと月の大半を占める ○ が凡例に無い。SP だけ凡例が上／Resy：店のカレンダーは空き・破線の一部・取り消し線の休み・#cacaca の受付外の4つで、凡例が無い）。作るときは、カレンダーの上に凡例を常に1行で出す。
4. 日付は「開始」と「終了」の2つで URL に持つと、1日でも範囲でも同じ形で引き継げる（DICE：`?from=…&until=…`／TableCheck：`date_from=…&date_to=…`、1日でも両方入る／Shakespeare's Globe：選んだ日＋7日を `unixDay` の範囲で問い合わせるが、URL は `#day` だけで残らない）。
5. 枠や部屋を選んでも、その場に合計の値段が出ない。値段は別の画面にある（TableCheck：予約フォームで数量を選んでも合計が無い／Othership：時間割の行にも枠の詳細にも値段が無く、料金は別ページの券／星野リゾート：空室カレンダーで日を選んでも「大人2名(1泊) ／名 50,750円〜」と1名の値段だけで、合計 154,300円は部屋のプランで初めて出る／Resy：一覧にも時刻の格子にもパネルにも金額が無く、$〜$$$$ の段だけ）。作るときは、枠を選んだ時点で人数を掛けた合計（税込）を、選んだ枠のすぐ下に出す。
6. 残りが少ないことを、見た目で区別していない（TableCheck：満席の時刻を #bfbfbf on #f7f7f7＝1.72:1 で残すだけ／Othership：残り3席の「3/20 Open」も「59/64 Open」と同じ 14px 700 #474747／Shakespeare's Globe：70行中1行の「LIMITED TICKETS」は値段の行と同じ 13px 700 #222、SP は 8.32px で値段 11.52px より小さい）。チームラボプラネッツは逆の例で、残りの少ない行だけ「残り28枚」を #f04137 で足す（ただし 3.81:1 で、境目は不明）。作るときは、残りを数字で出し、少ない枠（定員の2割以下など）は色と言葉を替える。
7. 残りの部屋・席の数は、少ないときだけ数字で出し、多いときは印か何も出さない（じゃらんnet：○＝10室以上・▲＝4〜9・1〜3室は数字／星野リゾート：1〜5室は「残りN室」、6室以上は値段だけ。375升のうち104升に帯／チームラボプラネッツ：26行のうち2行だけ「残り28枚」「残り48枚」、カレンダーは ○ と △ の印だけ）。作るときは、数字を出す境目を決めて（宿なら5室前後）、凡例にその境目を書く。
8. 宿の日付は、PC で2か月を並べて選ばせる（じゃらんnet：jQuery UI `numberOfMonths: 2`／星野リゾート：横断検索 870×481・空室カレンダーも2か月）。1か月の DICE・TableCheck は1日を選ぶ予約。チームラボプラネッツは1日を選ぶ入場だが、升に日ごとの値段を入れて PC で2か月を並べる。作るときは、泊まりの範囲を選ぶ画面と、日で値段が変わる画面は2か月、値段が同じで1日を選ぶ画面は1か月。
9. SP では、予約の入口を画面下に固定の帯にする（DICE：最安値とボタン 74px／TableCheck：71px／星野リゾート：「1泊1名 37,550円〜」と空室検索 77px）。Shakespeare's Globe の SP は逆に画面の上（ヘッダー直下 y=70）に 370×54 で貼り付き、頭のボタンが消えてから出す。チームラボプラネッツの SP は入場日時・枚数の画面に固定の帯が無く、展示ページは頭の 82×30 のボタンだけ。作るときは、帯に値段の単位（1泊1名・合計など）と、日付を選んだあとは合計を出す。
10. チケットの値段は、手数料を含めた額で出し、含んだことを値段のそばで1文に言う（DICE：「From £36.05」の下に「The price you'll pay. No surprises later.」／Shakespeare's Globe：「£89–£29*」の * で1注文 £3・1枚 £1 を含むと DETAILS と公演日の表の上で言う、立ち見は除く）。作るときは、合計の下に「うち手数料 ○円」の1行を出し、手数料の無い席種はそう書く。
11. 日で値段が変わるなら、カレンダーの升に「その日のいちばん安い値段〜」を入れ、何の値段か（大人1名・1泊1名など）を升の列のそばに書く（星野リゾート：空室カレンダーの升 61×61 に「50,750円〜」、単位は「大人2名(1泊) ／名」／チームラボプラネッツ：升 51×67 に「4,400~」12px、注記「カレンダー日付の下の表示はエントランスパス（大人）の料金」）。升の最安値は、その日の中のどの枠・部屋の値段かを、選んだ先の一覧で同じ数として見せる（プラネッツの 4,400 は 20:30 の枠の値段）。
12. 飲食の一覧は、カードにその日の空き時刻を4つのボタンで並べ、残りは「+」「…」で店へ送る（TableCheck：118×36・4つ＋「+」／Resy：101×40・4つ＋「…」、SP 3つ）。時刻のボタンが店の名前より強い色の主役になる（TableCheck #292929・Resy #336dde の塗り）。作るときは、時刻の下に席の種類か残りの数を1行で添え、時刻を指定されたらその前後の4つを出す。
