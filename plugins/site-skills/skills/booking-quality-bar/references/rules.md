# 横断ルール：予約のサイトをまたいで効いていること

2つ以上のサイトで同じ結果になったことだけを、番号つきで書く。1サイトだけの発見は `types/<slug>.md` に置く。
書くときは（〇〇と△△で確認）のように、元になったサイトを添える。

1. 払い戻し・キャンセルの条件は、最初の予約ボタンより下に置かれがちで、実測すると買う枠から遠い（じゃらんnet：ボタン y=683 に対し規定 y=3070／DICE：枠 y=547 に対し条件 y=1034、SP も同様／TableCheck：予約フォームの主なプランに規定が無く、一部のプラン説明の※1行と、ページ最後の「関連する規約とポリシー」だけ／Othership：時間割の行と枠の詳細に無く、規約ページと店ページの料金カードの「12 HOUR LATE CANCEL WINDOW」だけ）。作るときは、ボタンと同じ枠の中か、すぐ下の1行に入れる。
2. 予約サイトの1ページは重い。JS が最大の荷物になる（じゃらんnet 2.78〜7.60MB／DICE 8.33〜14.42MB／TableCheck 一覧・店 13.94〜15.60MB／Othership 6.13〜12.89MB、どれも PC。TableCheck は3ページとも JS 1本 10.04MB（転送 2.38MB）。DICE は公演ページでもヘルプでも Stripe 1.1MB・reCAPTCHA 約840KB×3 を読む。Othership は時間割の無い規約ページでも予約エンジンの /js 322KB を読む）。予約エンジン・決済・ボット対策のスクリプトは、選択を始めるまで読まない形を目指す。
3. 空きの記号（○・▲・×）の凡例は、記号のそばに出ていない（じゃらんnet PC：凡例は「?」の中／TableCheck の詳細：○・×・定休日に凡例なし）。作るときは、カレンダーの上に凡例を常に1行で出す。
4. 日付は「開始」と「終了」の2つで URL に持つと、1日でも範囲でも同じ形で引き継げる（DICE：`?from=…&until=…`／TableCheck：`date_from=…&date_to=…`、1日でも両方入る）。
5. 枠や部屋を選んでも、その場に合計の値段が出ない。値段は別の画面にある（TableCheck：予約フォームで数量を選んでも合計が無い／Othership：時間割の行にも枠の詳細にも値段が無く、料金は別ページの券）。作るときは、枠を選んだ時点で人数を掛けた合計（税込）を、選んだ枠のすぐ下に出す。
6. 残りが少ないことを、見た目で区別していない（TableCheck：満席の時刻を #bfbfbf on #f7f7f7＝1.72:1 で残すだけ／Othership：残り3席の「3/20 Open」も「59/64 Open」と同じ 14px 700 #474747）。作るときは、残りを数字で出し、少ない枠（定員の2割以下など）は色と言葉を替える。
