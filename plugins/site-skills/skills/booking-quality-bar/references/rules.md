# 横断ルール：予約のサイトをまたいで効いていること

2つ以上のサイトで同じ結果になったことだけを、番号つきで書く。1サイトだけの発見は `types/<slug>.md` に置く。
書くときは（〇〇と△△で確認）のように、元になったサイトを添える。

1. 払い戻し・キャンセルの条件は、最初の予約ボタンより下に置かれがちで、実測すると買う枠から遠い（じゃらんnet：ボタン y=683 に対し規定 y=3070／DICE：枠 y=547 に対し条件 y=1034、SP も同様／TableCheck：予約フォームの主なプランに規定が無く、一部のプラン説明の※1行と、ページ最後の「関連する規約とポリシー」だけ）。作るときは、ボタンと同じ枠の中か、すぐ下の1行に入れる。
2. 予約サイトの1ページは重い。JS が最大の荷物になる（じゃらんnet 2.78〜7.60MB／DICE 8.33〜14.42MB／TableCheck 一覧・店 13.94〜15.60MB、どれも PC。TableCheck は3ページとも JS 1本 10.04MB（転送 2.38MB）。DICE は公演ページでもヘルプでも Stripe 1.1MB・reCAPTCHA 約840KB×3 を読む）。予約エンジン・決済・ボット対策のスクリプトは、選択を始めるまで読まない形を目指す。
3. 空きの記号（○・▲・×）の凡例は、記号のそばに出ていない（じゃらんnet PC：凡例は「?」の中／TableCheck の詳細：○・×・定休日に凡例なし）。作るときは、カレンダーの上に凡例を常に1行で出す。
4. 日付は「開始」と「終了」の2つで URL に持つと、1日でも範囲でも同じ形で引き継げる（DICE：`?from=…&until=…`／TableCheck：`date_from=…&date_to=…`、1日でも両方入る）。
