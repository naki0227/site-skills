No surprises later.」／Shakespeare's Globe：「£89–£29*」の * で1注文 £3・1枚 £1 を含むと DETAILS と公演日の表の上で言う、立ち見は除く）。作るときは、合計の下に「うち手数料 ○円」の1行を出し、手数料の無い席種はそう書く。 逆の例が Barbican で、公演ページは「From £34 (including a £4 transaction fee)」、券売り場の升は券面の「from £30」で、同じ回の最安が £4 ずれる。一覧と詳細で同じ規則にそろえる。 Concertgebouw は逆で、値段は手数料抜き（€69〜€29）、「Prices do not include transaction fee: € 5 per order」を席種の表のすぐ下に1行。抜きで出すなら、この形で表の直下に置く。
11. 日で値段が変わるなら、カレンダーの升に「その日のいちばん安い値段〜」を入れ、何の値段か（大人1名・1泊1名など）を升の列のそばに書く（星野リゾート：空室カレンダーの升 61×61 に「50,750円〜」、単位は「大人2名(1泊) ／名」／チームラボプラネッツ：升 51×67 に「4,400~」12px、注記「カレンダー日付の下の表示はエントランスパス（大人）の料金」）。升の最安値は、その日の中のどの枠・部屋の値段かを、選んだ先の一覧で同じ数として見せる（プラネッツの 4,400 は 20:30 の枠の値段）。Relux：プランの升 67.6×88.8 に2名1泊「¥65,522〜」13.5px、単位は升の外に無く、面の下の「2名」と「合計」から読むしかない。 東京スカイツリー：升 92.3×64 に「¥2,800」14px、単位は暦の下に「※表示価格は大人料金」。大人は5段（2,000〜3,200円）、回廊つきは常に +1,200・こどもは半額なので、大人1種の升で全部の値段が決まる。 はとバス：出発日の暦の升 107×141 に「11,100円」13px 700（大人1名・平日）と「12,500円」（土日祝）。何の値段かは升にも暦のそばにも無く、ページ上の要約の「料金（大人1名）」だけ。 強羅花壇（2026-11-17）：公式の暦の升 87×84 に「69,850 円～」10px、単位は暦の下に「※表示料金は予約できる 1室1名1泊目 の最安値」13px。空いた部屋の型が1つの日は「〜」を付けない（「106,850 円」）。予約エンジンの升 62×79 は「154,850」と単位も無い。
12. 飲食の一覧は、カードにその日の空き時刻を4つのボタンで並べ、残りは「+」「…」で店へ送る（TableCheck：118×36・4つ＋「+」／Resy：101×40・4つ＋「…」、SP 3つ）。時刻のボタンが店の名前より強い色の主役になる（TableCheck #292929・Resy #336dde の塗り）。作るときは、時刻の下に席の種類か残りの数を1行で添え、時刻を指定されたらその前後の4つを出す。 逆の例がポケットコンシェルジュで、カードに時刻を出さず、日付と時刻を入れると件数だけが減る（97件→53件）。どの時刻が空いているかは店を開くまで分からない。
13. 宿の取り消し料は、取り消す日の段ごとの表でプランの中に出す（星野リゾート：40〜8日前10%・7〜0日前30%・不泊100%・事務手数料1,000円を率で／Relux：「2026年11月18日 (1日前)の0時〜 ¥48,630 (宿泊料金の50%)」の形で日付・円・率を4行）。星野リゾートは閉じた見出しの中、Relux は開いたまま予約ボタンより上。作るときは、選んだ日程と人数で計算した日付と円を主に、率を従にして、無料の期限を表の上に1行で大きく書く。
14. チケットの一覧・回の行には、席種ごとの値段を並べる。最安値1つより多くを一覧の段で見せる（Shakespeare's Globe：公演日の表の行に「PRICES: £89.00 - £29.00* | STANDING: £5.00」／Philharmonie de Paris：カードに「€13｜€27｜€42｜€62｜€78｜€88」、売り切れた席種だけ取り消し線）。DICE は「From £36.05」の1つだけ。作るときは席種ごとの値段を並べ、売り切れは消さずに線で残し、読み上げにも「売り切れ」と伝える。 Concertgebouw は一覧のカードが「from €29.00」の1つだけで、席種の5つの値段は公演ページの表（列の下に色の線 4px）にある。
15. 押せない部品（ボタン・人数・時刻）を薄い色にするだけで、押せない理由を言わない（DICE：買うボタンが #666／#333＝2.2:1 と ◆ だけ／チームラボプラネッツ：7つの同意を入れるまで「次へ」が opacity .2 だけ／Relux：料金カレンダーの「決定」がアウトを選ぶまで淡い紺だけ／ポケットコンシェルジュ：日を替えると枠の min〜max の外の人数が disabled、#342f28 on #1d1a16＝1.31:1、11/5 は2名だけ・11/12 は2〜4名と言う文が無い）。作るときは 3:1 以上の字で残し、そばに理由と次の手（「この日は2名だけ。3名からは11/12」）を1行で出す。 東京スカイツリー：「注文へ進む」を #8fbcf0 に白字（1.98:1）にし、何が足りないか言わない。人数は8人で ＋ が止まるが、上限の文が無い。 SHIBUYA SKY（2026-11-19）は人数の上限の8枚で「購入上限に達しました」を出すが、押せない「注文へ進む」（#a0aca9 on #eef1f0＝2.06:1）には理由の文が無い。

16. 在庫が場所・部屋・波で分かれるなら、分かれた単位ごとに別の行・別の升にして、同じ時刻を並べる（Othership：Free Flow を Sauna 1〜6 の部屋ごとに別の行、20:00〜21:45 に15分おきの8本／Lost Shore Surf Resort：Reef Left と Reef Right を別の週の升（423px）にし、教室も Beginner・Lessons Left・Right で別の升）。作るときは、単位の名前を升の頭の帯に書き、PC では横に、SP ではタブで切り替える（Lost Shore の SP は6つを横に 2,531px 並べ、最初の升も土日が切れる）。
17. 枚数・人数の上限を、その枠の残りの数にする（Philharmonie de Paris：席の画面の select の上限が残りの 1・3・4／Lost Shore Surf Resort：大人と子どもの数量の合計が「10 entries left」に届くと両方の＋が disabled、opacity .65）。どちらも上限の理由を数量のそばに書いていない（Lost Shore は頭に「10 entries left」20px）。作るときは、残りの数を数量の欄の横に書き、上限に届いたら「残り◯なので、ここまで」と1行出す。
18. 宿の取り消し無料の締めは、入りの日から逆算した日付（と時刻）でプランの行に1行で出すと、予約ボタンより上に来る。日付を替えたら締めも替える（Relux：「2026/11/15までキャンセル無料」12px が予約 146×48 と同じ行／白井屋ホテル：「2026/12/02 23:59まで(現地時間) はキャンセル料がかかりません。」、12/12 泊にすると 12/04 に動く）。段の表まで日付と円で出しているのは Relux だけ。 逆の例があさば（予約番）で、「宿泊日の14日前00:00まで」の相対の文を閉じた面の中に置き、日付にしない。 由縁 新宿（tripla、2026-11-21）：「2026/12/13 23:59まで(現地時間)」＝入りの3日前、値段より上（PC y=940・値段 y=1,177）、入りを替えると動く。押した面は率だけで円が無い。
19. 「残りわずか」の段は、残りの数ではなく定員との比で決まっていて、その境目は画面に出ていない（Lost Shore Surf Resort：availability の色は定員との比で、同じ残り4が緑にも赤にもなる／Barbican：ソースで `t/capacity*100<10`、1,152席の115席以下で「Last few」、凡例なし）。作るときは境目を1つに決め、凡例に「定員の1割（○席）以下」と数で書き、少ない回は数も出す。 逆の例が東京スカイツリーで、境目は定員との比ではなく数（ソース `Ft=30`、残り30以下で △）。ただし数も境目も画面に出さない。 Concertgebouw も同じで、公演のデータに `capacity` と `remaining` を持ち、20回を並べると残り÷定員 12.2% 以下が「Last tickets」、15.3% 以上は何も出ない。残り2の回も残り168の回も同じ札で、凡例も数も無い。 逆の例：LINKTIVITY のエンジン（東京スカイツリー 2026-11-07・SHIBUYA SKY 2026-11-19）は定員と関係なく残り30以下で △（`Ft=30`）。どちらも境目は画面に無い。 Wigmore Hall（2026-11-22）は比でなく数で、JS に `totalAvailableSeatsForConstituent<=5` で「Limited Availability」（数なし）。お気に入りの一覧だけ 5 より多く 300 未満で「◯ Seats Left」と数を出す。
20. 入口のページの「〜から」の値段と、予約の画面の最安がずれる（Barbican：一覧の升は券面の「from £30」、公演ページは手数料込みの「From £34」／東京スカイツリー：公式の「天望デッキ 1,800円～」と JSON-LD の lowPrice 1800 に対し、予約の暦の92日〔2026/11/7〜2027/2/6〕の最安は 2,000円）。作るときは入口の「〜から」を予約のデータから出し、何を含むか（手数料・大人1人）を同じ言葉で書く。
21. 飲食の席の時間（◯時間制）は、予約の枠を選ぶ画面に出ず、別の面か FAQ にだけある（ポケットコンシェルジュ：「※2.5時間制」はコースの「詳細を見る」の面だけ／Dishoom：人数で 90・105・120・150分に変わる duration は API と FAQ だけで、升・検索の帯に0語）。作るときは、人数の欄のそばか合計の段に「2名・90分の席」と書き、人数を替えたら書き替える。 Zenchef（Septime、2026-11-16）：API の `turn_times` は人数によらず12枠（3時間）だが `show_turn_times: false` で画面に出さない。
22. 受付・休業を言う文と、空きのデータが食い違う（TableCheck：お知らせ「日曜のディナーは休業」に対し 11/22(日) の夜に ○／Dishoom：夕方の受付の境目が /reservations/「6pm」、FAQ「5.45pm、例外は Manchester と Birmingham」、SevenRooms「6pm〜9.30pm」の3通りで、API は Covent Garden・2名で 16:15〜21:15 が無く、例外に無い Glasgow に夕方11枠）。作るときは、受付の時間帯と休業日を1つのデータに持ち、文も升もそこから作る。
23. 公式サイト・予約の画面とも、和文の Web フォントがいちばん重い荷物になる（東京スカイツリー：予約エンジンが Noto Sans JP を切らずに4本 8.69MB で、日時のページの半分以上／あさば：公式のトップで Adobe Fonts の秀英明朝2本 6,671KB、8.49MB の 79%。客室ページでも 6,278KB）。作るときは、和文の Web フォントは見出しだけにするか切れ端を小さく読み、予約の1ページで書体を 1MB 未満にする。 由縁 新宿（2026-11-21）：公式のトップで Adobe Fonts の源ノ明朝・源ノ角ゴを3つの太さずつ6本 31,720KB（56.59MB の56%）、文字だけの Q&A でも 28,799KB。

24. 公演を探す暦に、公演のある日の印が無い。過ぎた日と公演の無い日も、押せる日と同じ見た目（DICE：日付のカレンダーに印なし／Philharmonie de Paris：暦に公演の印が無い／Barbican：What's on の暦に上演の印が無い／Concertgebouw：v-calendar の1か月に印が無く、過ぎた1〜13日も押せる見た目、押すと `?date=` で「その日から先」）。作るときは、公演のある日に印、売り切れの日は別の印、過ぎた日は押せなくし、凡例を暦のすぐ下に1行で出す。（Oper Leipzig 2026-11-18：v-calendar の升 60×48、上演の印なし、11/1〜17 の過ぎた日も aria-disabled="false"・cursor:pointer。Concertgebouw と同じ部品・同じ欠け）
25. 同じ演目のほかの回は、選んでいる回の買う枠のそばに、回ごとの状態つきで並べる（Philharmonie de Paris：題の下に「日・時刻・空き」のチップ 約118×99、押すと右の枠の席種が入れ替わる／Concertgebouw：券の枠 440×336 の中の「Other dates」に日付・時刻・「Last tickets」・View concert）。どちらも残りの数は出さない。作るときは「残り◯席」を数で出し、押したら読み直さずに枠の中身を替える。

26. 暦の操作（日を押す・月を送る）で、ページ全体を読み直す（じゃらんnet：空室カレンダーの日を押すたびに約0.9MB／チームラボプラネッツ：日を押すたびに約1.6秒／はとバス：「次の月」で PC 6,502ms・+2,120KB、URL に空の引数20個と `display_date=2026-12`）。作るときは、受付の範囲（2か月など）の空きを1度に持ち、月送りと日の選択はその場で替える。URL には選んだ月と日だけを残す。 強羅花壇（reservation.jp、2026-11-17）：プランの空室状況の暦で日を押すと、PC 8,286ms・+1,070KB（SP 9,131ms・+1,318KB）でページごと読み直す。月送りは +151KB で読み直さない。 逆の例が SHIBUYA SKY（2026-11-19）で、開いた時に /calendar を1回（102日分）読み、日・プラン・枠・人数の操作は API 0本・0KB。


27. 「今日」と「明日」を、店の時間帯でなく見る人の端末か店の営業の区切りで決め、画面の別の場所と食い違う（Dishoom：店の1日の始まり 06:00 で既定の日を決め、深夜 01時に帯は「7 Nov」、下の行は「Today 8 Nov」／Septime の Zenchef：同じ 01:04 UTC に、端末が Europe/Paris と America/New_York なら最初のチップが「Mon 16 Today」、Asia/Tokyo なら過ぎた休みの日「Sun 15 Yesterday」。どちらも時刻に店の時間帯を書かない）。作るときは、今日を店の時間帯の暦の日で決め、店の外から見る人には時刻に「パリ時間」と自分の時刻を添える。
28. 部屋の型が1室ずつの宿では、「残り◯室」がいつも1になり、少ないことを伝えない（あさば〔予約番〕：週の帯の14升すべて「1 室」／強羅花壇〔reservation.jp〕：1/23 の部屋の行11のうち8に「残り 1 室」、2室以上ある型3つは何も出ない）。作るときは、1室ずつの部屋は残りの数を出さず「空き」と書き、その日程で空いている部屋が1つだけのときに「この日程で空いているのはこの部屋だけ」と言う。
29. 公式サイトの空室の暦と、予約の画面の暦・見出しで、同じ日の値段の範囲が違うのに、どの範囲の値段かを升のそばで言わない（強羅花壇：公式の暦の 1/23 は宿全体の最安 62,850円～、エンジンのプラン×花香の暦は 162,850、読み直した見出しは 125,700円~〔2名・スタンダード A〕／東京スカイツリー：公式の「1,800円～」に対し予約の暦の最安 2,000円、規則20）。作るときは、升の上に「宿全体の最安／この部屋の値段」を言葉で書き、押した先の見出しに同じ値段を出す。

30. 回の状態は、一覧の行の右端の同じ場所で、ボタンの言葉とボタンの有無で言い分ける。売り切れはボタンを消すか言葉を替え、次の手（譲り場・待ちの名簿・詳しく）へつなぐ（Concertgebouw 2026-11-14：「Last tickets」「Sold out」18px 600 をボタンの下に、売り切れはボタンが「More information」／Oper Leipzig 2026-11-18：BUY TICKETS 140×61・REMAINING TICKETS 182×61 は同じ黄の塗り、SOLD OUT はボタンを消して字にし TICKET EXCHANGE と、待ちの名簿のある回だけ WARTELISTE、無料は ENTRANCE FREE の字、売らない回は何も出さない）。どちらも「少ない」に数を付けない。作るときは、少ない段に数と色、売り切れの次の手はその回で絞って開く。 Wigmore Hall（2026-11-22）：BOOK NOW 220×40（黒の塗り）と SOLD OUT（白地に #c4c4c4 の枠 1.74:1、押せない）の2つだけ。売り切れの判定 isSoldOut は残りの数と別で、残り2〜4席の回も SOLD OUT。取りやめの回も題の頭の「Cancelled:」と SOLD OUT（JS の CANCELLED は使われていない）。
31. 英語版の画面に、元の言語の語と規定が残る。とくに買う手前の言葉と取り消しの決まり（Philharmonie de Paris 2026-11-02：払い戻し不可・48時間前の交換は仏語の CGV だけ／Oper Leipzig 2026-11-18：英語版でも WARTELISTE・ⓘ の説明・日程の見出し「Termine & Tickets」・クッキーの窓・約款の h3 18のうち9がドイツ語）。作るときは、ボタン・説明・規定の語を言語ごとの1つの表から引き、訳の無い語を出さない。
32. 時刻で入場の値段が替わるなら、値段の段を時刻の枠に結びつけて出す。どちらも段の理由（混雑・日の入）は画面に書かない（チームラボプラネッツ 2026-10-30：30分ごとの行に 5,200〜4,400円の5段／SHIBUYA SKY 2026-11-19：〜14:59 2,700円と 15:00〜 3,400円の2つのプランに分け、カードに単価。高い側は10日先まで19枠とも売り切れ）。作るときは段の境目の時刻と理由（「日の入 16:35 の前後」など）を券か枠の並びに書き、高い側から売り切れる日は暦の升に券ごとの状態を出す。

33. 受付をまだ開けていない日を、休みの日と同じ見た目にする（Septime の Zenchef：開ける前の日は輪なしで休みと同じ／Disfrutar の CoverManager：受付の端 2027-11-20 より先の営業日23日を close_date の黒にし、同じサイトの年の暦はその日を Opened にする）。作るときは「◯月◯日 10:00 に開く」の見た目と言葉を休みと分け、凡例にも1行足す。 由縁 新宿の tripla（2026-11-21）：Q&A は「5か月前の1日から一斉販売」、API は 5月からを disabled_dates で返すのに、暦は満室と同じ斜線と「満室」の吹き出し（宿でも同じ）。
34. 空きが人数で変わるのに、どの人数なら入れるかを言葉で言わない（ポケットコンシェルジュ：枠の min〜max の外の人数を disabled にするだけ／Septime の Zenchef：別の人数なら空きを破線の輪だけで、凡例なし／Disfrutar の CoverManager：日を押すと人数の欄が 4・5 だけになり、12か月で2名は0日と言わない）。作るときは、選んだ日の残りの卓を「4〜5名の卓だけ」と書き、人数ごとに入れる日の数を一覧の見出しで言う。
35. 取り消しの率を、公式サイトの足・FAQ・予約の画面の何か所にも書く宿で、数が食い違うことがある（強羅花壇 2026-11-17：予約の面4行と FAQ の PDF 6行で食い違い）。そろえている宿は、予約の面だけ「無料の期限」「連絡なし」の行を足し、ほかは同じ率（由縁 新宿 2026-11-21：公式の足・Q&A・tripla の面とも 2日前 20％・前日 50％・当日 100％）。作るときは規定を1か所のデータから全部の画面に出し、「サイトやプランで異なる」と書くなら、どのプランが違うかを予約の面に書く。
36. 空きの無い選択肢を、選ぶ前に画面から外す。0件の値で迷わせない（Barbican 2026-11-06：絞り込みの選択肢に件数を付け、0件の選択肢と値が1つしか無い欄は出さない／Wigmore Hall 2026-11-22：座席表の凡例は、その回に空きのある値段の段だけ。il Pomo d'Oro の回は £18 の段が消えて4段）。ただし Wigmore のおまかせの表は「£18.00 0 available」の行と枚数の欄を残す。作るときは、凡例と選択肢は空きのあるものだけにし、消した段は「空きの無い段は出していません」と1行で言う。
37. 残りの数が出るのは、席を選ぶ画面の奥の1か所だけで、一覧と公演ページは「買える／買えない」の2値（Philharmonie de Paris 2026-11-02：席の画面の枚数の上限が残りの数、一覧は取り消し線だけ／Wigmore Hall 2026-11-22：おまかせのタブだけ「£50.00 20 available」、一覧と公演ページは BOOK NOW と「Tickets Available」）。作るときは、席の画面で持っている段ごとの残りの数を、一覧の行と公演ページにも同じデータから出す。
