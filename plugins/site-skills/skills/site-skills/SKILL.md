# どのスキルを使うか選ぶ

種類ごとのスキルは、実在のサイトを解剖して育てた、その種類**専用**の品質基準。
作るものに合わないスキルを使うと、型が逆に働く（例：EC の商品一覧に LP の「常に動く主役は1つ」を当てる）。最初にここで選ぶ。

## 作る前に決めること
スキルを選ぶ前に、次の4つを決める。わからないものは、もっともらしい仮定を1行で書いて進める（作るのを止めない）。
- そのページでしてもらう、ただ1つの行動（買う・予約する・試す・応募する・読み進める）
- 相手はだれか、どこから来たか（広告・検索・SNS・メール・既存の利用者）
- 相手がまだ動かない理由を3つ（値段・手間・信用など）
- 出せる証拠（数字・導入先・声・保証）

## 選び方
1. 作る・直すものを1文にする（だれに・何をしてもらうページか。上で決めた「ただ1つの行動」を入れる）。
2. 下の表の「してもらうこと」で、**主のスキル**を1つ選ぶ。サイトの種類ではなく、**そのページ**でしてもらうことで選ぶ（会社のサイトの中の採用ページなら `corporate-quality-bar`、通販サイトの中の特集ページなら `lp-quality-bar`）。
3. 主のスキルが「流れ・構成」のスキルで、見た目の雰囲気も決める必要があるときは、**副**として `lp-quality-bar` を足す（最大2つ）。
4. 選んだスキル名と理由を一言で伝えてから、そのスキルの `SKILL.md` を読み、その手順に従う。
5. 主と副で決まりが食い違うときは、主のスキルを優先する。
6. 作り終えたら、`references/ai-tells.md`（AIっぽさの見直し）を全部当てはめ、当てはまったところを作り直してから出す。
7. 表のどれにも当たらない（管理画面、ダッシュボード、ゲーム本体の画面、メールなど）ときは「当てはまるスキルが無い」と伝え、近いスキルの `checklist.md` だけを参考にする。

## してもらうことで選ぶ
| してもらうこと | 主のスキル | よくあるページ |
|---|---|---|
| 1ページで知ってもらう・申し込んでもらう | `lp-quality-bar` | LP、特設ページ、周年サイト、ブランドサイトのトップ、ポートフォリオ |
| 商品を探して買ってもらう | `ec-quality-bar` | 商品一覧、商品詳細、カート、検索結果 |
| 作品の世界に入って、遊ぶ・見る・行く準備をしてもらう | `game-quality-bar` | ゲーム・アニメ・イベントの公式サイト、キャラクター紹介、購入・事前登録 |
| 会社を信頼してもらい、用事（取引・採用・投資）に進んでもらう | `corporate-quality-bar` | コーポレートサイト、会社概要、事業紹介、採用サイト、問い合わせ |
| 道具を理解して、試す・契約してもらう | `saas-quality-bar` | 製品サイト、機能紹介、料金表、導入事例 |
| 記事を読んで、次も読んでもらう | `media-quality-bar` | 記事ページ、ブログ、オウンドメディア、ニュース、記事一覧 |
| 空きを探して予約してもらう | `booking-quality-bar` | 空室検索、日付選択、空き状況、プラン一覧 |

## 迷ったとき
- 1ページで完結し、流れ（一覧→詳細など）が無い → `lp-quality-bar`。
- 流れがある → その流れの終わり（買う・予約する・試す・応募する・読み進める）で選ぶ。
- それでも迷ったら `references/catalog.md` で各スキルの説明を読み比べる。

## このスキルの範囲
- 選ぶだけ。品質基準の中身は、選んだスキルの側にある。
- 各スキルは解剖のたびに増えていく。見本がまだ無い下位タイプは、そのスキルの問い（`viewpoints.md`）とチェックリストだけで作る。
