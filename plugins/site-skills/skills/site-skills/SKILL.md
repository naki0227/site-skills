# どのスキルを使うか選び、AIっぽくなく作る

種類ごとのスキルは、実在のサイトを解剖して育てた、その種類**専用**の品質基準（値はどれも、どのサイトで測ったかが書いてある）。
このスキルは、①どれを使うか選び、②作る前に考えを決め、③作った後に測って見て直す、までを受け持つ。

## 1. 作る前に決めること（`references/make.md` に詳しく）
**最初に `references/taste.md`（ユーザーが好きと言った実在のサイトの台帳）を読む。** ほかの決まりと食い違ったら、台帳が勝つ。
わからないものは、もっともらしい仮定を1行で書いて進める（作るのを止めない）。
- そのページでしてもらう、ただ1つの行動と、相手（だれが、どこから来たか）
- **題材の棚卸し**：この題材にしかない物を8〜12個（名前の由来、場所と通り、数字、制約、素材と色、決まった時刻や手順、その世界の紙もの＝時刻表・札・伝票・のぼり）
- **考えの一文**：「このページでは〔棚卸しの1つ〕が〔部品〕になる」。いちばん近い競合の名前を入れても成り立つなら、考え直す
- **見本を集める**：何を参考にするか（構成・配色・文字・動き）を先に決め、`references/galleries.md` の事例集から同じ業種を5〜10件選び、`node scripts/sample.js <URLを1行ずつ書いたファイル> <出力.jsonl>` で色・書体・ボタン・罫を測って、真似る値を1行ずつ書く（`references/aesthetic.md`「業種の手本を先に測る」）。頭の中の「〇〇っぽさ」で色や書体を決めない
  - 手本の URL は、まず選んだ種類のスキルが解剖したサイト（`<種類>-quality-bar` の types/・notes/ に出てくる URL）から取る。足りないときだけ事例集を手で探す。この環境のネットワークで開けないサイトもある（一発テストで18件中4件しか測れないことがあった）。3件測れたら先に進む。
- **主張と証拠の列**：1章に1つの主張と、それを信じさせる物（写真・数字・実演）。主張の無い章は作らない
- **触れる1つ**：題材の本物の中身で動く、操作できる部品を1つ（例：時刻を進めると出欠表が変わる）

## 2. スキルを選ぶ
1. 作るものを1文にする（だれに・何をしてもらうページか）。
2. 下の表の「してもらうこと」で**主のスキル**を1つ選ぶ。サイトの種類ではなく、**そのページ**でしてもらうことで選ぶ（会社のサイトの中の採用ページなら `corporate-quality-bar`、通販サイトの中の特集ページなら `lp-quality-bar`）。
3. 主のスキルが「流れ・構成」のスキルで、見た目の雰囲気も決める必要があるときは、**副**として `lp-quality-bar` を足す（最大2つ）。主と副で食い違うときは主を優先する。
4. 選んだスキル名と理由を一言で伝えてから、そのスキルの `SKILL.md` を読み、その手順に従う。
5. 表のどれにも当たらない（管理画面、ダッシュボード、ゲーム本体の画面、メールなど）ときは「当てはまるスキルが無い」と伝え、近いスキルの `checklist.md` だけを参考にする。

| してもらうこと | 主のスキル | よくあるページ |
|---|---|---|
| 1ページで知ってもらう・申し込んでもらう | `lp-quality-bar` | LP、特設ページ、周年サイト、ブランドサイトのトップ、ポートフォリオ |
| 商品を探して買ってもらう | `ec-quality-bar` | 商品一覧、商品詳細、カート、検索結果 |
| 作品の世界に入って、遊ぶ・見る・行く準備をしてもらう | `game-quality-bar` | ゲーム・アニメ・イベントの公式サイト、キャラクター紹介、購入・事前登録 |
| 会社を信頼してもらい、用事（取引・採用・投資）に進んでもらう | `corporate-quality-bar` | コーポレートサイト、会社概要、事業紹介、採用サイト、問い合わせ |
| 道具を理解して、試す・契約してもらう | `saas-quality-bar` | 製品サイト、機能紹介、料金表、導入事例 |
| 記事を読んで、次も読んでもらう | `media-quality-bar` | 記事ページ、ブログ、オウンドメディア、ニュース、記事一覧 |
| 空きを探して予約してもらう | `booking-quality-bar` | 空室検索、日付選択、空き状況、プラン一覧 |

迷ったとき：1ページで完結し流れが無い → `lp-quality-bar`。流れがある → その流れの終わり（買う・予約する・試す・応募する・読み進める）で選ぶ。それでも迷ったら `references/catalog.md` を読み比べる。

## 決まりが食い違ったときの順（上が勝つ）
一発テスト（2026-11-07）で、4人とも「どの決まりが先か」で迷った。迷ったらこの順で決め、負けた決まりの WARN は理由を1文書いて残す。
1. ユーザーがその場で言ったこと
2. `references/taste.md` の「いまの好み」
3. 選んだ種類のスキル（`<種類>-quality-bar`）の実測の値。構成・流れ・中身・状態（いつ・どこ・値段・手順）はこちらが決める
4. `references/aesthetic.md`（日付つきの記録。いちばん上の「最初の画面の作り方の方向」が下の回より先）
5. `scripts/inspect.js` のしきい値
- よくある食い違いの決め方：題の大きさは taste（大きな字でよい。jp-head-size は残す）。写真の量は taste（形で抜く。photo-cover は残す）。主の色は題材の世界から（青を決まりにしない。taste.md）。日付・時刻・値段の大きさは種類のスキル（大きく、最初の画面に字で）。
- 題材が架空で「その題材にしか無い物」が足りないときは、その世界にある本当の決まり・道具・紙もの（整理券、時鐘の数え方、雪吊り）を設定として足してよい。足したら「架空」と画面に書く。

## 3. 作る順番
0. **最初の画面の形を、`references/taste.md` の「いまの好み」で決める。** 最初の画面の型は2つあり、どちらも好き：①題材の物の形の窓で写真を抜き、大きな字・飾りと重ねる（ふねの古本市など、いままでの作例）②「大きなタイポグラフィ＋人の写真をバーンと」（taste.md）。依頼で型を言われたらそれに、言われなければ題材で選ぶ（人が主役の題材――人が来る教室・催し・採用・選手・作り手――は②も候補）。②のとき：人の写真は、題材のまわりの世界で人が大きく写っている物を `scripts/photos.js` で探し、背景を消して切り抜くか（aesthetic.md「切り抜きはきちんと」）、題材の形の窓で大きく抜く。写真の人を題材の店の人・社員として見せない（何が写っているかと「〇〇の人ではありません」を書く）。切り抜くときは、無地（白・灰）の背景で撮られた写真を選ぶと早い（髪の毛先が背景と同じ色だと穴が開く）。OpenCV が無ければ `pip install opencv-python-headless`。切り抜いた画像も credits.json に1行足す（元の写真と同じ作者・ライセンスで、題に「切り抜いた。元：〇〇.jpg」）。切り抜いた画像（透過の WebP・PNG）の img には `data-object` を付ける（inspect が切り抜きとして数える）。題材が架空で、主の色を取る物が無いときは、その世界にある色の物を設定として足し、架空と書く（例：床のバミリテープの緑）。 題材の世界の物（場所・道具・紙もの・乗り物）から「写真を抜く窓の形」と「飾りの形」を1〜2個取り（例：フェリーなら丸窓と救命浮環と信号旗）、好きな組み方（大きな字＋形で抜いた写真＋線や形を1枚に重ねる。明るく、遊びがある）で組む。写真に白い字を中央に乗せる・社員の写真を並べる・グラデーションに一行、のような「どこかで見た形」は使わない。
1. 色は3色（地・主・差し色）、分け方の比率、題の置き方を `references/aesthetic.md` で先に決め、CSS の先頭に書く（これが主。ユーザーが X/Y の比較で選んだ順番）。**主の色は題材の世界の物（看板・道具・素材・制服・季節）から取り、`examples/*/index.html` の先頭のコメントにある主の色と同じ色相にしない。** 青が続いたら、その題材の世界のほかの色（焼き色・松の緑・真鍮・紙の色）を主にする。
   - いまの作例の主の色（2026-11-07）：ふねの古本市・パン屋・割り勘アプリ・吹奏楽・庭師＝青（#1d3fcf〜#1e3f99）、町工場＝紺 #12305f、窯元＝辰砂の赤 #8e1d3b、印刷会社＝金赤 #c8102e、サウナ＝翡翠 #0b6f6b、焙煎所＝琥珀 #e8a93a、銭湯＝朱 #c9341a、陶器市＝焦げ茶と朱、学童アプリ＝赤 #b02a22、パフェ＝紫 #5b2a86、文具＝きみどり #b5dc3c、犬のサロン＝藤色 #7452b8、美容室＝カットクロスの深緑 #1f6b3f（色相145°）、ダンス教室＝バミリテープの緑 #0a8049（152°）。色相の目安：青 225〜230°、翡翠 178°、紫 270°、藤 260°、きみどり 75°。主の色は、ほかの作例と色相を20°以上離す。辰砂 #8e1d3b は桃色に近いので、桃色・赤紫を主にするときは避ける。
   - 作ったら、index.html の先頭のコメントに `主の色：#xxxxxx（由来）` の1行を書く（次の作り手が grep 1回で比べられるように）。選んだスキルの見本の値は、構成・流れ・文字の段・状態の支えに使う。
2. 動きなしで、最初の画面 → 各章の順に作る。最初の画面の考えを、料金・よくある質問・フッターまで運ぶ（最初の画面だけ作り込んで、あとが定番の部品になるのが一番多い失敗）。**各章を1枚の画面として見て「これがヒーローでも好きか」で作る**（`taste.md`「下の章はヒーローと別々にしない」）：
   - ヒーローの部品（形で抜いた写真・大きな字・色の面・飾りの形）を、章の中でも大きく、端からはみ出させて主役に使う。見出しの横の小さな飾りにしない。見出し＋文＋表の段に戻さない。
   - **どの章にも、本物の人か場面を1つ入れる。** `scripts/photos.js` で、題材のまわりの世界で人が写っている写真を探す（例：古本市なら神田古本まつり・bouquinistes、催しなら festival crowd、店なら market stall、仕事なら workshop の作業）。何が写っているかと出典を写真の横に書き、題材そのものの写真として見せない。人の写真が無ければ、棚・道具・人を描き込んだ場面の絵（断面図・見取り図）にする。店の看板・ロゴ・商品名が主に写る写真は使わない（写り込んだ小さな看板は、窓の切り取りで見えなくする）。同じ写真を切り方を変えて何章にも使い回さない（使い回すくらいなら場面の絵にする。ユーザーは断面の絵の案も「いい」と言った）。部品を重ねて細かくするだけでは埋めない（「煩雑」と言われた）。
3. 中身は全部書く（メニューは全品と値段、部屋は1つずつ）。取り除いた飾りの跡は、別の飾りで埋めない。大きさ・本物の中身・写真の枠・色の面で埋める。
4. 触れる1つを、その主張を証明する章に入れる。動きは最後に足す。

## 4. 作った後：測る → 見る → 直す（3回まで）
1. `node scripts/inspect.js <index.html>` を通す（このスキルのフォルダの `scripts/`。写真は `scripts/photos.js` で探す。`references/make.md` 6）。PC 1440px とスマホ 390px で、本文の大きさ・小さい文字・枠線の数・影・グラデーション・見出しの上の小さなラベル・通し番号・絵文字・書体の数・横スクロールを測る。**FAIL が0になるまで直す**。WARN は、理由を1文で言えないなら直す。
2. スクリーンショットを全部自分の目で見て、`references/critique.md` の見方で批評を書き、上位3つの問題を直す。下の章は1章ずつ撮り、3つの問いで自分で判定して、1つでも「いいえ」の章を直す：①ヒーローの部品（窓の形・大きな字・色の面・飾り）が、その章でも主役の大きさで出ているか ②本物の人か場面があるか ③見出し＋文＋表（またはカードの列）だけの段に戻っていないか。実在サイトの下の章と並べて比べるのは、ネットワークで開けるときだけでよい（一発テストでは3回とも撮れなかった）。
   - HTML で組んだ題材の物（名刺・レシート・整理券・製品の画面）は、その要素に `data-object` を付けると、inspect の photo-text-only が「絵・札」として数える。飾りに付けて検査を通すことはしない。
   - inspect の WARN のうち、大きな日本語の題（jp-head-size）・写真が覆う割合（photo-cover）・SVG の形（svg-hero）・橙のボタン（orange-cta）は、台帳の好みに寄せると出る。台帳に寄せた理由を1文で書けば残してよい。
3. `references/ai-tells.md`（AIっぽさの見直し）を全部当てはめる。
4. 報告には、考えの一文・触れる1つ・inspect の結果・批評の点数と残った問題を書く。測っていないことを測ったと書かない。

## このスキルの範囲
- 選ぶことと、作る前後の手順だけ。見た目の値の中身は、選んだスキルの側にある（このスキルは値を決めない）。
- 各スキルは解剖のたびに増えていく。見本がまだ無い下位タイプは、そのスキルの問い（`viewpoints.md`）とチェックリストだけで作る。
