# 好みの台帳（ユーザーが「好き」と言った実在のサイト）

作る前に、`aesthetic.md` より先にこれを読む。食い違ったら、ここが勝つ。
集め方：事例集（I/O 3000・MUUUUU.ORG・81-web・SANKOU!・Web Design Clip）に最近載った実在のサイトの最初の画面（PC 1440px）を10個並べて見せ、「これどう？」と聞く。答えはユーザーの言葉のまま書き、次の回は、寄せた方向と外した方向を混ぜて見せる。
サイトの画像は入れない（URL と、見えたものの言葉だけ）。

## いまの好み（第1〜5回と、作ってみた第1〜3回のまとめ。回を足すたびに書き直す）
- **ヒーローの型「大きなタイポグラフィ＋人の写真をバーンと」**（2026-11-07、ユーザーの言葉「ヒーローにタイポグラフィと人の写真バーンって」）：画面の幅いっぱいの大きな字と、大きな人の写真（切り抜きか、形で抜いた写真）を1枚に組む。好きな実在サイトでは yoichi-shumputei.com（青の地に切り抜いた落語家と筆の字の名前）・miraiz-persol.jp（切り抜いた人と縦書きの大きなコピー）・heartdemic.heralbony.com（幅いっぱいのセリフ体と人の動画）・kanayama-g.co.jp/recruit-lp（人の写真と大きな英字）。人は小さく遠くに写すのでなく、画面の高さの半分以上の大きさで。字と人を前後に重ねる（字の一部が人の後ろに隠れる、人が字の前に出る）。
- 手本の作例：`examples/funehon/index.html`（ふねの古本市）。ユーザーが通して見て「いいんじゃない？」と言った最初の1枚。見た目を写さず、組み方（題材の窓の形・3色・下の章まで同じ部品・どの章にも人）を写す。
- **嫌い：どこかで見た形。** 写真の上に白い字のコピーを中央に置きボタンを添える（第3回 B・H・J、第4回 B）、社員の写真を並べる（第4回 F）、グラデーションに一行（第4回 D）、暗い地に細い英字だけ（第4回 H）、光る線（第3回 G）、丸い写真を散らす（第3回 F）、写真を置いただけ（第1回 G・I）、カードを並べるだけ（第1回 J）、詰め込みすぎ（第4回 G）。
- **派手か静かかは関係ない。** 余白の多い縦書き（第2回 meoto.jp）も、太い英字だけ（第1回 carnilove）も好き。好きなものには、**そのサイトにしか無い作り込み**が最初の画面にある：字の置き方（縦書き・斜体・切れた大きな英字・明朝の一行）、絵、切り抜き、線。
- **いちばん好き（3回とも同じ方向）**：wedding.tonami-komuro.com（第3回）、miraiz-persol.jp（第4回）、dokomi.de/ja（第5回）。3つとも**青が主**で、**写真を形で抜く**（軌道の線の中・不定形・角の丸い窓）。大きな字・写真や切り抜き・線や形を1枚に重ねて組み、写真は字と形の間に置く部品にする。明るく、遊びがある。
- 青でなくても、組み方が同じなら好き（第5回の青緑 D・橙 F・緑 H）。いちばんの3つが青だったのは手本がたまたま青だっただけで、**青は決まりではない**（一発テストで4つとも青にしたら「それぞれのいろが」と言われた。下の「一発テスト第1回」）。**主の色は題材の世界から取り、ほかの作例（`examples/` の index.html の先頭のコメント）と主の色が同じ色相にならないようにする。**
- **下の章はヒーローと別々にしない**（作ってみた第2回）：ユーザーの言葉「ヒーローと別々じゃない感じがしていい」。下の章を1枚ずつ見て「これがヒーローでも好きか」で作る。ヒーローの部品（形で抜いた写真・キャラクターや絵・大きな字・色の面）を、下の章でも大きく、端からはみ出させて使う。見出し＋文＋表の定番の段に戻さない。
- **下の章に本物の人と場面を入れる**（作ってみた第3回）：下の章が Y に負けた理由は、人と場面が無いことだった（図形と物の写真だけ）。人の写真を入れた案と、人や棚を描き込んだ断面の絵の案は、どちらも「いい」。どちらにするかは題材で決める（人が集まる催しなら本物の人の写真）。部品を重ねて細かくするだけの案は「煩雑」。
- ユーザーは「ヒーロー以外は何がいいのかわからない、判断ができない」と言った。下の章は1つだけ見せて良し悪しを聞かず、**実在の好きなサイトの同じ役目の章と2つ並べて「どっちが好き」**と聞く。
- 作るときは：最初の画面で「どこかで見た形」を1つも使わない。題材の字・線・絵・切り抜きのどれかで画面を組み、写真をそのまま置いて字を乗せるだけにしない。
