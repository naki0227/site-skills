# AIっぽさの見直し（仕上げに必ず通す）

出典：site-skills の使用例5つ（examples/、2026-10-26）をユーザーが「結構AIっぽい」と評価し、見比べて見つけた共通の癖。
どれか1つでも当てはまったら、作り直してから出す。

**種類ごとのスキルとの食い違い**：下の癖は「手本のサイトに無いのに、AI が埋め草として足すもの」のこと。手本のサイトが実際に使っている値（例：とらやの角丸23pxのボタン、びっくりドンキーの紙色の地）は使ってよい。ただしそのときも、最後の問い（名前を消して別の業種でも成り立つか）に答え、成り立ってしまうなら、題材の現場の物を足して崩す。

## 絵と写真
- **SVG の絵を主役にしない。** 茶碗・豆袋・建物・人物などを、線と塗りの平たいイラストで描いて最初の画面に置かない。どの使用例でも一目で AI 製に見えた最大の原因。
  - ただし実在のサイトは絵を使う：採用・製造業 12件中5件、地域の催し 10件中6件が、絵・図形・文字のキービジュアルを最初の画面の主役にしていた（2026-11-05、使用例の作り直しで撮った手本）。実在の絵は、写真・切り抜き・色の面と**重ねて**使い（DORO KOGYO の人物の絵と写真の角丸）、線の太さや塗りに手の跡がある。AI っぽいのは、平たい SVG の絵を1枚だけ主役に置くこと。
- **写真が入るはずの場所を、灰色の枠のままにしない。** 題材そのものの写真が無いときは、題材の「まわりの世界」（産地・道具・素材・町・季節）の**本物の写真**を、自由に使えるもの（Wikimedia Commons の CC0・CC BY・CC BY-SA）から探して使う（`scripts/photos.js`）。出典：ユーザーの見比べ（2026-10-26）。架空の陶器市の最初の画面で、①灰色の枠に撮るべき写真を書く、②色の面に大きな数字、③登り窯の形の区画図、④常滑の登り窯の実写＋出典、の4案から④を選んだ（AIっぽいと選ばれた案は無し）。
  - 決まり：写真は題材の物（店・人・商品）として見せない。キャプションは「何が写っているか」を書き（「登り窯の焚き口側（常滑）。鴨谷焼の窯も同じつくりです」）、出典（作者・Wikimedia Commons・ライセンス）を画面に小さく出す。解剖した相手のサイトの画像は使わない。
  - 実写が見つからないときの順：題材の情報そのもの（図・表・地図）→ 題材の色の面と大きな文字。灰色の枠は最後の手段で、残すなら報告に書く（`scripts/inspect.js` の grey-slot）。
  - 画像の生成（作り物の写真）は使わない：架空の題材の物を本物に見せることになる。
- 写真に頼らず見せられるもの（時刻表・料金表・地図・図面・在庫・メニュー・数値の表）は、それ自体をきちんと組んで主役にする。情報が主役のサイトは、情報の組み方で質が決まる。
- 同じ形の絵を色だけ変えて並べない（同じ豆袋12個、同じアイコン6個）。

## 言葉
- **格言調の見出しにしない。** 「AはBだ。」を読点で区切り、句点で決める2行（「サウナは、60分ずつ6人まで。」「回るものを、止めない。」）は使わない。見出しは、相手が知りたいことをそのまま書く（「十条湯のサウナを予約する」「機械オペレーター 2名募集 月給24.6万円〜」）。
- 英字の小見出し（SAUNA RESERVATION など）を、日本語の見出しの上に同じ意味で小さく重ねない（AI っぽいと選ばれた）。英字そのものを名前・ナビ・章の題として使うのはよい（下の「表記」）。

### 表記：英字・カタカナ・漢字・ひらがな（2026-11-02）
ユーザーの問い「漢字を使うところと、ひらがなを使うべきところを研究してほしい」「日本語が要るのは説明のときだけで、英字やカタカナ英語を使ってもいいのでは」を受けて、`galleries.md` の Web Design Clip の業種別（各45件、新しい順）と、ファッション（MUUUUU.ORG ほか）の日本語のサイト計275件のトップページの文字を、役割ごとに数えた。

| 宿・旅（35） | 44／17／36% | 37／49／11% | 46／38% | 17・12・30・41% |
| メディア・出版（29） | 37／8／45% | 8／53／37% | 16／61% | 30・15・26・29% |
| IT・Webサービス（34） | 61／7／27% | 22／55／21% | 17／58% | 19・20・30・32% |

- **英字にしてよい所**：店名・ナビ・章の題・商品名・コレクション名・短く意味の決まった語（SHOP・MORE・SALE）。ナビは IT 61%・宿 44%・飲食 40% が英字。ファッションの商品名は7割以上が英字（`aesthetic.md` の表と同じ事例集）。
- **日本語にする所**：説明・値段と条件（税込・送料・時間・料金）・結果のある行動のボタン（「来店予約」「登録する」「詳しく見る」）・エラー・法律の表記。ボタンは宿（英字 46%）以外のどの業種も日本語が多数。
- 採用は全部の役割で日本語が多い（ナビ 57%・ボタン 72%）。相手が会社の言葉に慣れていないので、英字を減らす。メディアは章の題の英字が 8% と少ない。
- **ひらく（ひらがなで書く）言葉**：どの業種でもほぼひらがな。漢字：ひらがなの回数（8業種の合計の例）は、ください 11:297・いただく 15:233・できる 13:338・いたします 11:94・こと（形式名詞）3:412・ため 7:190・まで 0:399・私たち 6:152。すべて・および・または・さらに・ぜひ も多くはひらく（「又は」は会社で 2:0 と漢字もある）。`scripts/inspect.js` の hyouki が、ください・いただく・できる・いたします・こと・ため・まで・私たち の漢字を WARN にする。
- **漢字のまま書かれる言葉**：お客様（採用以外は漢字が多い。ファッション 31:8、宿 21:0）、丁寧（全業種で漢字）、皆様（採用だけ「皆さま」14:0）、一人ひとり（混ぜ書き）。様々／さまざま・良い／よい・共に／ともには業種で割れる（飲食は「良い」16:10、採用は「様々」16:9）。
- 限り：トップページだけ。数の少ない言葉は目安。正規表現で数えたので、「仕事」の「事」などは除いたが、拾い漏れや誤りが少し残る。

- 「〜なら」「〜を、もっと」「〜のすべてを」で締める見出し、体言止めの連打をしない。

### 文章は「店の人が書く言葉」で（ORBITO の試作への指摘、2026-11-01）
ユーザーの言葉：「見出しとか文章とか、なんでこんなAIが作った感がすごいんだろう」。見た目の決まりを全部守り、inspect が FAIL 0 / WARN 0 でも、文章だけでAIに見えた。inspect は文章の型をほとんど測らない（filler-words だけ）ので、ここは自分で読んで直す。
| 書いてしまった文 | 何がAIっぽいか | 直した文 |
|---|---|---|
| 「クールな宇宙服も、同じ棚で選べる洋品店」 | 作る前に書いた**特色の1行（設計メモ）をそのまま見出しにした**。「Aも、Bで〜できる〇〇」は企画の説明で、店の看板ではない | 「宇宙服の洋品店」 |
| 「船外活動から月面の散歩まで、42着。」 | 「AからBまで、N」の幅＋数の決め文句 | 「26秋冬の新作6型が入荷しました。」 |
| 「試着は、水の中で」 | 上の格言調（読点で区切って決める）。決まりがあったのに破った | 「試着の予約」 |
| 「上の COOL と CUTE を切り替えると、ここの色名も替わります」 | **画面の仕掛けを読む人に説明している**。仕掛けは触れば分かる | 消した |
| 商品ごとに「月面の散歩用。肘とひざに月の砂よけの二重布」 | **全部の行に気の利いた一言を、同じ調子で付けた**。気の利き方が均一なのが機械っぽい | 種類（「月面用スーツ」）・色名・税込の値段・サイズだけ |
| 「出発ロビーから歩いて3分」「休み：打ち上げのある日」 | 店の決まり文句（徒歩・定休日・営業時間・税込）を避けて、わざわざ柔らかく言い換えた | 「徒歩3分」「定休日」「営業時間」 |

- 実店舗の商品の並びは素っ気ない：Allbirds・Tracksmith の一覧のカードは、画像・商品名・色名・価格・色の見本・サイズ数だけ（ec-anatomy `types/apparel.md`）。説明の一言は付いていない。
- **見出しと文は、その業種の人が実際に使う言葉で書く**（店なら 新作・入荷・税込・定休日・営業時間・店舗情報、募集なら 月給・勤務地）。言い換えて個性を出さない。個性は写真・色・構図・商品そのもので出す。
- 面白さ（ここでは「打ち上げ当日は休み」）は、ページ全体で1〜2か所まで。全部の文が気が利いていると、書いた人がいない文になる。
- 作る前に書いた「特色の1行」「考えの一文」は設計のメモ。画面に出さない。
- **折り返しを決めてから出す。** 「2色で／す。」「試着でき／ます。」のように、語の途中や最後の1〜3字で行が分かれると、それだけで雑に見える（ユーザーの指摘：「言い回しを変えなくても、改行が変なところにならないようにすべき」2026-11-01）。
  - `<html lang="ja">` と `word-break:auto-phrase`（Chrome 119〜、文節で折り返す）、`text-wrap:pretty` を本文・見出しに。
  - 最初の画面の文・写真の出典・注記のような短い文は、意味の切れ目で `<br>` を入れて行を決める（「26秋冬の新作6型が入荷しました。<br>全型、COOL と CUTE の2色です。」）。人名など切りたくない語は `&nbsp;` でつなぐ。
  - 収まらないときは、言い回しを短くして行に合わせる（「浮いた状態で試着できます」→「浮いたまま試着できます」）。
  - `scripts/inspect.js` の line-break が、語の途中の折り返しと、最後の行が1〜2字の文を数える（PC とスマホの両方で）。
- **本文を灰色にしない。** ORBITO 第3版は本文の84%が灰色（地との差 7:1 未満）で、ユーザーに「グレー使いすぎ」と言われた。測ったファッション10件は本文を #000〜#1e1e1e（暗い地なら白に近い色）で組み、灰色は商品の補足（色・サイズ）・注記・出典だけ。本文は地との差 7:1 以上に（inspect：grey-body、本文の4割を超えると WARN）。
- 書き終えたら、見出しと最初の画面の文だけを抜き出して読み、「この業種の本物のサイトにこの言い方があるか」を1つずつ確かめる。無ければ本物の言い方に替える。

## 部品と並び
- **数字3つの横並び**（導入数・利用者数・継続率など）を最初の画面に置かない。数字は、それを確かめたい場所（料金・事例・募集要項）に置く。
- 主ボタンと副ボタンの2つ並びを、どのページでも同じ形で置かない。最初の画面の主な行動は1つ。
- ①②③の丸数字の手順、丸いアイコンに小見出し、角丸のカードを等間隔に並べるだけの章を、手本のサイトに無いのに使わない。
- 画面の端で流れ続ける帯（マーキー）を、題材に理由が無いのに使わない。

## 線と箱・文字の大きさ（測って分かったこと）
出典：site-skills の使用例5つと実サイトの計測（2026-10-26、`scripts/inspect.js` と同じ測り方）。
- **四辺を囲む箱を区切りに使わない。** 最初の3画面で枠線のある要素は、実サイト（とらや 4・ほぼ日 15・Linear 14・teamLab 1・Apple 1）に対して、使用例は 29〜138 個だった。区切りは余白か、地の色の1段の差でつける。囲むのは表・入力欄・押せる物だけ。
- **本文を小さくしない。** 30字以上の文の大きさは、とらや 16px・ほぼ日 16px（スマホ 15px）・Apple 17px に対して、使用例の陶器市・焙煎所・銭湯は 11〜14px で、本文のうち13px未満が 38〜69% あった（学童アプリ・町工場は作り直しで16px以上）。本文は16px以上、注記も13px以上。teamLab（12px）や星野リゾート（10px）のように小さい実サイトもあるが、taste-skill の調査でも「上位サイトの欠点（真似しない）」とされている。
  - **例外：写真が主役の業種（ファッションなど）。** 事例集のファッション80件の本文の中央値は 13〜14px（レディース 13px、モード・セレクト 14px）で、肌着・ナチュラルだけ 16px だった（2026-11-02、`scripts/sample.js`）。ユーザーの許可で、手本の業種の実測が 16px 未満なら、その中央値（14px まで）に合わせてよい。13px 未満の本文は使わない。

## 色と文字
- ベージュ・薄いピンク・薄い灰の「やわらかい無難な地」に**理由なく**逃げない（題材の特色に合うなら使ってよい。静かなカフェのクリーム、やわらかい雑貨のパステルなど。`aesthetic.md`「この表は正解ではなく選択肢」、2026-11-01）。手本にしたサイトの地の色と、題材の現場の色（藍ののれん、鋳物の黒、焙煎の焦げ茶など）から決める。
- 全部同じゴシック体にしない。題材に合えば明朝・等幅・手書きの文字（画像でなく書体）を使い、太細や大小の対比をはっきりさせる。
- 雰囲気を題材に合わせる。町工場を開発ツールの黒地に、銭湯を北欧カフェの淡色にしない。

## ユーザーの見比べ（A/B）で確かめたこと
出典：十条湯の同じ中身で1か所だけ変えた見本9組を、ユーザーが「どちらが AI っぽいか」で選んだ結果（2026-10-26）。9組中7組が、ここに書いた癖の側を選んだ。`scripts/inspect.js` の WARN にもしている。
| 見比べ | AI っぽいと選ばれた側 | 決まり |
|---|---|---|
| 枠 | 部品を全部、四辺の枠で囲む | 囲まない。区切りは余白と地の色（上の「線と箱」） |
| 文字の大きさ | 本文12px・見出し15px | 本文16px以上（上の「線と箱・文字の大きさ」） |
| 色 | 小さな色のラベル（緑・紫・橙・赤）を散らす | 色は1色を広い面（帯・地）で。状態の色は文字の色だけ。丸いラベルを散らさない（inspect：many-hues・pill-chips） |
| 角と影 | 角丸14pxのカードにぼかした影 | 角は四角かまるに1回で決め、カードを丸めて浮かせない（inspect：soft-radius・shadow） |
| 見出し | 英字の小見出し＋格言調の2行 | 知りたいことをそのまま書く（上の「言葉」） |
| 地の色 | 淡いベージュ `#f4efe7` | 地は白か現場の色（上の「色と文字」） |
| 揃え方 | 全部を中央揃え | 本文は左揃え。中央は1か所だけ（inspect：centered） |
| 余白のつり合い | 枠で囲んだ箱の中の余白を上下10px・左右14pxにしたほう。ユーザーの言葉では「下の余白が小さすぎて気持ち悪い。バランスの問題」（箱どうしの間の広さではなかった） | **箱の中の余白は、下を上と同じか少し広く、左右より狭くしない**（例：14px なら 14 / 14 / 18）。最後の要素の margin-bottom・表の最後の罫・中の枠が、箱の下の線に付いていないかを見る。文字は行の下に半分の行間があるので数字の上では足りて見えても、罫や枠で終わる箱は詰まって見える（inspect：tight-bottom） |
| 「※」の注記の量 | 同じくらい（差が無い） | 注記の多さは AI っぽさの決め手ではない。決まりにしない（ただし注記も13px以上） |

## 情報の密度：1画面に主役を1つ
出典：ユーザーの指摘「情報量の密度も気にしてほしい」（2026-10-26）を受けて、画面1枚（高さ1画面分）ごとの文字数と塊（段落・項目・セル・見出し・ボタン）の数を、実サイトと使用例で同じ測り方で測った（ヘッダー・ナビ・フッターと隠れた物は除く。`scripts/inspect.js` の dense-screen・dense-first）。
| PC 1440px | 塊／画面（中央値） | 文字／画面（中央値） | 最初の画面の文字 |
|---|---|---|---|
| とらや | 4 | 132 | 132 |
| ほぼ日 | 3 | 288 | 102 |
| Apple（AirPods Pro） | 3 | 144 | 166 |
| Linear | 3 | 424 | 368 |
| SmartHR | 6 | 192 | 56 |
| じゃらん（宿の検索） | 21 | 185 | 343 |
| 使用例5つ（直した後） | 8〜38 | 341〜654 | 331〜756 |
- **使用例は、実サイトの2倍の文字を、5〜10倍の数の小さな塊に分けて1画面に詰めていた。** 小さい文字・多すぎる箱と同じ根から出ている癖で、「全部を一度に見せたい」と詰めるほど AI っぽくなる。
- 1画面に主役を1つ。塊は3〜6個を目安にし、減らした分、残した物を大きくする。検索結果・一覧・表のように、相手が比べるために密に見たい画面だけは多くてよい（じゃらん 21）。そのときも理由を1文で言えるようにする。
- 最初の画面は、題・それが何かを言う1文・主な行動・主役の物（写真・触れる部品）だけ。説明・注意書き・数字は下の章へ。
- 「取り除くだけでは足りない」とは食い違わない：薄く散らすのでなく、少ない物を大きく、中身は章を分けて全部書く。

## 状態と本物らしさ
- 押せる物には、ホバー・押したとき・キーボードのフォーカス・読み込み中・空・エラーの状態を作る。`#` だけのリンクを残さない。
- 完了の文は落ち着いて具体的に（「田中さんに請求書を送りました」）、エラーは何が失敗して次に何をするかを書く。感嘆符で盛り上げない。
- 数字はキリのいい数にしない。人名・店名は地域と業種に合わせ、使い回さない。
- 中身の無い言葉を使わない：「革新的な」「シームレスな」「次世代の」「〜を、もっと自由に」「〜のすべてを」「あなたらしい」「新しい体験を」。何をするかを平たく書く。
- 実在しない顧客の声・導入社数・評価の星を作らない（`make.md` 3）。

## 取り除くだけでは足りない
出典：taste-skill の目隠し比較（定番の飾りが多くても中身の厚いページが、飾りを取っただけの薄いページに毎回勝った）。
- 飾りを消した跡を、別の飾りで埋めない。**大きさ**（主役をもっと大きく）、**本物の中身**（全メニュー・全部屋・時刻表）、**写真の枠**、**色の面**で埋める。
- 何も無い画面（半画面以上の空き）が2つ以上あるなら、作り足りていない。

## 最後の問い
- そのページから店名・社名を消して、別の業種の名前を入れても成り立つなら、まだ AI っぽい。題材でしか成り立たない部品が、最初の画面に1つ以上あるか。

## 代わりに何をするか（作り直しで AI っぽさが消えた手）
出典：examples/ の5つを作り直したときに、実際に効いたこと（2026-10-26）。

- **現場の紙と道具を部品にする。** 題材の現場に実際にある物を、画面の部品の形にする。
  - 陶器市：のぼり（縦書きの題）、手書きの値札、番号入りの会場図（examples/toukiichi）
  - 焙煎所：焙煎予定の黒板（焙煎日・5kg 釜の空き・着日）、クラフト紙の豆ラベル、焙煎記録の用紙（examples/roastery）
  - 銭湯：藍と紅ののれんで男女を選ぶ、下足札の木札で時間を選ぶ、番台の手書きの料金板、伝票の中に内訳（examples/sento）
  - 町工場：見学日のホワイトボード、検査記録票の中の図面、作業日報の1日の流れ（examples/machikoba-recruit）
- **写真が無いときの最初の画面は、相手がいちばん知りたい情報そのものにする。** 会場図＋2日の時刻表＋雨の日の1行／焙煎予定の黒板／予約の部品／募集要項の5行（仕事・給料・休み・経験・場所）。どれも、最初の画面にイラストを置いていたときより、ずっと本物らしく見えた。
- **色は現場の物から1つずつ拾う。** のぼりの織部の緑、焦げ茶とクラフト紙と朱の判、のれんの藍と紅、作業着の紺と安全表示の黄黒。地は白か現場の色にして、淡いベージュに逃げない。
- **書体を役目で分ける。** 名前と見出しは明朝、数値・日付・品番は等幅、現場の手書き（値札・黒板・料金板・日報のメモ）は手書きの書体、本文はゴシック。
- **和文の Web フォントは、使う字だけ読む。** Google Fonts の `text=` で使う字だけに絞ると、銭湯の例で 約911KB → 約82KB になった（examples/sento）。
- **数字は、それを確かめたい場所に置く。** 最初の画面に並べず、料金表・募集要項・時刻表の行の中へ。
