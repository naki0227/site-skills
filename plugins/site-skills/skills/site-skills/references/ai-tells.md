# AIっぽさの見直し（仕上げに必ず通す）

出典：site-skills の使用例5つ（examples/、2026-10-26）をユーザーが「結構AIっぽい」と評価し、見比べて見つけた共通の癖。
どれか1つでも当てはまったら、作り直してから出す。

**種類ごとのスキルとの食い違い**：下の癖は「手本のサイトに無いのに、AI が埋め草として足すもの」のこと。手本のサイトが実際に使っている値（例：とらやの角丸23pxのボタン、びっくりドンキーの紙色の地）は使ってよい。ただしそのときも、最後の問い（名前を消して別の業種でも成り立つか）に答え、成り立ってしまうなら、題材の現場の物を足して崩す。

## 絵と写真
- **SVG の絵を主役にしない。** 茶碗・豆袋・建物・人物などを、線と塗りの平たいイラストで描いて最初の画面に置かない。どの使用例でも一目で AI 製に見えた最大の原因。
- 写真が入るはずの場所は、本物らしい写真が無いなら「写真の枠」にする。枠には、撮るべき写真を具体的に書く（例：「窯出しの朝、棚に並ぶ湯呑み。縦4:5、自然光」）。絵でごまかさない。
- 写真に頼らず見せられるもの（時刻表・料金表・地図・図面・在庫・メニュー・数値の表）は、それ自体をきちんと組んで主役にする。情報が主役のサイトは、情報の組み方で質が決まる。
- 同じ形の絵を色だけ変えて並べない（同じ豆袋12個、同じアイコン6個）。

## 言葉
- **格言調の見出しにしない。** 「AはBだ。」を読点で区切り、句点で決める2行（「サウナは、60分ずつ6人まで。」「回るものを、止めない。」）は使わない。見出しは、相手が知りたいことをそのまま書く（「十条湯のサウナを予約する」「機械オペレーター 2名募集 月給24.6万円〜」）。
- 英字の小見出し（SAUNA RESERVATION など）は、手本にしたサイトが使っているときだけ。
- 「〜なら」「〜を、もっと」「〜のすべてを」で締める見出し、体言止めの連打をしない。

## 部品と並び
- **数字3つの横並び**（導入数・利用者数・継続率など）を最初の画面に置かない。数字は、それを確かめたい場所（料金・事例・募集要項）に置く。
- 主ボタンと副ボタンの2つ並びを、どのページでも同じ形で置かない。最初の画面の主な行動は1つ。
- ①②③の丸数字の手順、丸いアイコンに小見出し、角丸のカードを等間隔に並べるだけの章を、手本のサイトに無いのに使わない。
- 画面の端で流れ続ける帯（マーキー）を、題材に理由が無いのに使わない。

## 線と箱・文字の大きさ（測って分かったこと）
出典：site-skills の使用例5つと実サイトの計測（2026-10-26、`scripts/inspect.js` と同じ測り方）。
- **四辺を囲む箱を区切りに使わない。** 最初の3画面で枠線のある要素は、実サイト（とらや 4・ほぼ日 15・Linear 14・teamLab 1・Apple 1）に対して、使用例は 29〜138 個だった。区切りは余白か、地の色の1段の差でつける。囲むのは表・入力欄・押せる物だけ。
- **本文を小さくしない。** 30字以上の文の大きさは、とらや 16px・ほぼ日 16px（スマホ 15px）・Apple 17px に対して、使用例の陶器市・焙煎所・銭湯は 11〜14px で、本文のうち13px未満が 38〜69% あった（学童アプリ・町工場は作り直しで16px以上）。本文は16px以上、注記も13px以上。teamLab（12px）や星野リゾート（10px）のように小さい実サイトもあるが、taste-skill の調査でも「上位サイトの欠点（真似しない）」とされている。

## 色と文字
- ベージュ・薄いピンク・薄い灰の「やわらかい無難な地」に逃げない。手本にしたサイトの地の色と、題材の現場の色（藍ののれん、鋳物の黒、焙煎の焦げ茶など）から決める。
- 全部同じゴシック体にしない。題材に合えば明朝・等幅・手書きの文字（画像でなく書体）を使い、太細や大小の対比をはっきりさせる。
- 雰囲気を題材に合わせる。町工場を開発ツールの黒地に、銭湯を北欧カフェの淡色にしない。

## ユーザーの見比べ（A/B）で確かめたこと
出典：十条湯の同じ中身で1か所だけ変えた見本9組を、ユーザーが「どちらが AI っぽいか」で選んだ結果（2026-10-26）。9組中7組が、ここに書いた癖の側を選んだ。`scripts/inspect.js` の WARN にもしている。
| 見比べ | AI っぽいと選ばれた側 | 決まり |
|---|---|---|
| 枠 | 部品を全部、四辺の枠で囲む | 囲まない。区切りは余白と地の色（上の「線と箱」） |
| 文字の大きさ | 本文12px・見出し15px | 本文16px以上（上の「線と箱・文字の大きさ」） |
| 色 | 小さな色のラベル（緑・紫・橙・赤）を散らす | 色は1色を広い面（帯・地）で。状態の色は文字の色だけ。丸いラベルを散らさない（inspect：many-hues・pill-chips） |
| 角と影 | 角丸14pxのカードにぼかした影 | 角は四角かまるに1回で決め、カードを丸めて浮かせない（inspect：soft-radius・shadow） |
| 見出し | 英字の小見出し＋格言調の2行 | 知りたいことをそのまま書く（上の「言葉」） |
| 地の色 | 淡いベージュ `#f4efe7` | 地は白か現場の色（上の「色と文字」） |
| 揃え方 | 全部を中央揃え | 本文は左揃え。中央は1か所だけ（inspect：centered） |
| 余白のつり合い | 枠で囲んだ箱の中の余白を上下10px・左右14pxにしたほう。ユーザーの言葉では「下の余白が小さすぎて気持ち悪い。バランスの問題」（箱どうしの間の広さではなかった） | **箱の中の余白は、下を上と同じか少し広く、左右より狭くしない**（例：14px なら 14 / 14 / 18）。最後の要素の margin-bottom・表の最後の罫・中の枠が、箱の下の線に付いていないかを見る。文字は行の下に半分の行間があるので数字の上では足りて見えても、罫や枠で終わる箱は詰まって見える（inspect：tight-bottom） |
| 「※」の注記の量 | 同じくらい（差が無い） | 注記の多さは AI っぽさの決め手ではない。決まりにしない（ただし注記も13px以上） |

## 247サイトの調査で、弱いサイトに多かったもの
出典：[Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill)（MIT）の `references/research.md`（One Page Love と Awwwards の 247 サイト、2026-10）。上位＝採点 7.5 以上、下位＝6.5 未満。
| 癖 | 上位 | 下位 |
|---|---|---|
| アイコンを載せた特徴カードの横並び | 1% | 28% |
| 字間を広げた小さな英字のラベル（3つ以上） | 6% | 43% |
| 見出しの上の丸いラベル（New・Beta など） | 5% | 26% |
| グラデーションの面／文字のグラデーション | 22%／2% | 52%／13% |
| 止まっている物の影（5つ以上） | 10% | 30% |
| 絵文字 | 10% | 26% |
| 中央に見出し、その下に製品画面（ヒーローの型） | 7% | 24% |
| ボタンの中くらいの角丸（9〜16px） | 6%（四角 52%・まる 23%） | 24% |
同じ調査で、等幅の小さな文字・01/02 の通し番号・細い罫は、むしろ上位のサイトに多かった（今の流行）。だからこそ生成されたページが真っ先に真似る。手本のサイトが使っていないなら使わない。

## 状態と本物らしさ
- 押せる物には、ホバー・押したとき・キーボードのフォーカス・読み込み中・空・エラーの状態を作る。`#` だけのリンクを残さない。
- 完了の文は落ち着いて具体的に（「田中さんに請求書を送りました」）、エラーは何が失敗して次に何をするかを書く。感嘆符で盛り上げない。
- 数字はキリのいい数にしない。人名・店名は地域と業種に合わせ、使い回さない。
- 中身の無い言葉を使わない：「革新的な」「シームレスな」「次世代の」「〜を、もっと自由に」「〜のすべてを」「あなたらしい」「新しい体験を」。何をするかを平たく書く。
- 実在しない顧客の声・導入社数・評価の星を作らない（`make.md` 3）。

## 取り除くだけでは足りない
出典：taste-skill の目隠し比較（定番の飾りが多くても中身の厚いページが、飾りを取っただけの薄いページに毎回勝った）。
- 飾りを消した跡を、別の飾りで埋めない。**大きさ**（主役をもっと大きく）、**本物の中身**（全メニュー・全部屋・時刻表）、**写真の枠**、**色の面**で埋める。
- 何も無い画面（半画面以上の空き）が2つ以上あるなら、作り足りていない。

## 最後の問い
- そのページから店名・社名を消して、別の業種の名前を入れても成り立つなら、まだ AI っぽい。題材でしか成り立たない部品が、最初の画面に1つ以上あるか。

## 代わりに何をするか（作り直しで AI っぽさが消えた手）
出典：examples/ の5つを作り直したときに、実際に効いたこと（2026-10-26）。

- **現場の紙と道具を部品にする。** 題材の現場に実際にある物を、画面の部品の形にする。
  - 陶器市：のぼり（縦書きの題）、手書きの値札、番号入りの会場図（examples/toukiichi）
  - 焙煎所：焙煎予定の黒板（焙煎日・5kg 釜の空き・着日）、クラフト紙の豆ラベル、焙煎記録の用紙（examples/roastery）
  - 銭湯：藍と紅ののれんで男女を選ぶ、下足札の木札で時間を選ぶ、番台の手書きの料金板、伝票の中に内訳（examples/sento）
  - 町工場：見学日のホワイトボード、検査記録票の中の図面、作業日報の1日の流れ（examples/machikoba-recruit）
- **写真が無いときの最初の画面は、相手がいちばん知りたい情報そのものにする。** 会場図＋2日の時刻表＋雨の日の1行／焙煎予定の黒板／予約の部品／募集要項の5行（仕事・給料・休み・経験・場所）。どれも、最初の画面にイラストを置いていたときより、ずっと本物らしく見えた。
- **色は現場の物から1つずつ拾う。** のぼりの織部の緑、焦げ茶とクラフト紙と朱の判、のれんの藍と紅、作業着の紺と安全表示の黄黒。地は白か現場の色にして、淡いベージュに逃げない。
- **書体を役目で分ける。** 名前と見出しは明朝、数値・日付・品番は等幅、現場の手書き（値札・黒板・料金板・日報のメモ）は手書きの書体、本文はゴシック。
- **和文の Web フォントは、使う字だけ読む。** Google Fonts の `text=` で使う字だけに絞ると、銭湯の例で 約911KB → 約82KB になった（examples/sento）。
- **数字は、それを確かめたい場所に置く。** 最初の画面に並べず、料金表・募集要項・時刻表の行の中へ。
