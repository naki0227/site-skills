# 横断ルール：コーポレートのサイトをまたいで効いていること

2つ以上のサイトで同じ結果になったことだけを、番号つきで書く。1サイトだけの発見は `types/<slug>.md` に置く。
書くときは（〇〇と△△で確認）のように、元になったサイトを添える。

1. 採用への入口は、ヘッダーの常設ナビとトップの本文の両方に置く（LayerX：ナビ2か所＋Join Us の節、Valmont：Careers▾＋トップの入口03）。ヘッダーとフッターだけにした竹中庭園緑化は、トップの7区画のどこからも採用へ行けなかった。採用サイトの HILLTOP も応募の入口はヘッダーの ENTRY と最後の Join Us! の帯だけで、社員の声・仕事・数字の区画のあとには無い。Mistral AI はヘッダーの Company の下がり窓の4項目目だけで、トップの本文・フッター・相談の振り分けのどこにも無かった。日清食品グループもヘッダー右の「リクルート↗」だけで、商品のトップ（11,284px）と会社のトップのどちらの本文にも採用の入口が無かった。採用サイトの Life at Spotify は逆に、トップの最初の画面そのものが募集の束と検索で、Latest jobs・Wanna join us?・Quick clicks・フッターの Start Your Journey と、本文に5か所の入口がある。 由紀精密もトップの本文に採用の区画が無く、右下に浮くバナー（PC 画面の10.3%）が別ドメインのエンジニア採用サイトへ行くだけ。
2. 募集の一覧は外部の採用システムに任せ、自サイトは「どんな職場か」の話に絞る（LayerX：外部ATS、Valmont：Workday と LinkedIn、竹中庭園緑化：job-gear.net の採用サイト、Mistral AI：Ashby）。日清食品グループは総合採用サイトで新卒・キャリア・アルムナイに分け、グループ16社の採用サイト（12ドメイン、job-gear.net が3社）へ渡す。例外は Life at Spotify で、募集は自サイトの API（79件）、応募も自サイトの中の4段のシートで済ませ、外へ渡さない。 由紀精密は自サイトに3職種の募集要項を置き、応募はメール、エンジニアだけ別の採用サイト。
3. 採用ページは、その会社のページの中で一番重くなる。作るときは写真や動画に上限を決める（LayerX 6.51MB が最大、Valmont 14.85MB が最大、竹中庭園緑化 6.29MB がトップ 5.74MB より重く、解析タグを入れると GTM 14本で +7.3MB、採用サイトの HILLTOP はトップの動画が PC 用 60.7MB で、開いて10秒で 42MB）。採用だけのサイトでは逆にトップが一番重く、募集の一覧が一番軽い（Life at Spotify：top 14.50MB、/jobs 3.77MB で写真 0）。 中小の由紀精密は逆で、採用 2.23MB はトップ 8.59MB・事業 7.40MB より軽い（写真の多い事業とトップが重い）。
4. スクロール中もナビへ戻る手段を必ず残す。隠すなら戻し方を、隠さないなら画面をふさがない薄い帯にする（LayerX：左上の「ロゴ＋Menu」だけ残す、Valmont：上へ 38px 戻すと黒い浮きバー、竹中庭園緑化：隠さず白 .8＋blur 10px の丸い帯 97px）。HILLTOP は header が static で、PC ではスクロールするとナビへ戻る手段が無かった。日清食品グループは 94.5px を下へ 300px で隠し、上へ戻すと transform .4s で出す（Valmont と同じ形）。Life at Spotify はピルを隠さず浮かせ（地なし）、区画のページでは下へ読むと1段目だけ 40→−51px に逃がし、2段目を上に残す。ただし浮いたピルが本文の見出しに重なる。 由紀精密も fixed 64px の白を隠さず、事業ページでは 56px の2段目も残す。
5. トップに数字の帯は置かず、規模の数字は会社ページ（Valmont）か本文（LayerX）か会社概要の表（竹中庭園緑化：239名・9,500万円）に回している。採用サイトの HILLTOP も数字は専用のページ（/culture/ のタイル9つ）に回した。Mistral AI も社員「900+」は採用ページのタイルにだけ置き、会社ページには無い。作るときは会社ページに数字4つ前後を表の上に置く（LayerX は本文に、竹中庭園緑化は表の中に埋もれて弱かった）。日清食品グループも会社トップに売上・従業員の数字は無く、入口の格子と株価で代えていた。 由紀精密も数字は会社概要の2列の表の中だけ（38名・約200社）。
6. トップのニュースや事業の一覧はカードでなく全幅の行で並べる（LayerX：1行 192〜196px、Valmont：1行 210px・右に写真 308×188、竹中庭園緑化：1行 74px・日付→札→題）。 由紀精密も全幅の行 74px（日付→カテゴリ→題→矢印）。ただし flex で、題が2行の行は列が 9〜46px ずれた。
7. 見出しの文を二重に持つと、片方だけ直し漏れる（LayerX：PC 用と SP 用の見出し、Valmont：PC 用・SP 用の1文の片方だけ「has a been」、竹中庭園緑化：SVG の見出しと alt が3か所違う）。文は1つだけ持ち、分けるのは見た目の側だけにする。 由紀精密：製品名が沿革では「AP-0」、メニューとフッターでは「AP-01」。
8. 問い合わせフォームに用件の選択が無いと、採用・買い物・取引の相談が同じ5欄に混ざる（Valmont：5欄で用件無し、竹中庭園緑化：5欄すべて必須で用件無し）。振り分けたのは LayerX（フォームの前にリンク5つ）と Mistral AI（左に Support・Press・Privacy・Vulnerability の4つ）で、どちらも採用の振り分けは無い。採用サイトの HILLTOP は FAQ の「お問い合わせはこちらから」がエントリーフォームへ来る。作るときはフォームの前で振り分け、用件を選ばせる。 由紀精密は振り分けた4窓口（精密加工・技術開発・広報・採用）に採用を入れた最初の例で、「工場見学は原則お断り」と受けないことも書く。
9. `prefers-reduced-motion` を見ていても一部だけで、動きが止まりきらない（Valmont：最初の画面だけ、竹中庭園緑化：CSS に1つも無く、reduce でもトップで16個が動く、HILLTOP：0で、reduce でも数え上げ・棒・社員カードの流れ・動画が動く、Mistral AI：グラフ・地球・視差の3か所だけで、積み木の物理・10秒で回るタブ・ロゴの帯は reduce でも動く）。作るときは、浮き・差し替え・スクロール連動を全部止める。日清食品グループは CSS 8本すべてで 0 で、CM の自動再生とヘッダーの隠れが reduce でも動く。Life at Spotify は CSS で 0か所、止まるのは JS で見る都市の帯だけで、最初の画面の縮み・4秒と2秒の自動送り・出てくる絵・見出しを打つ動きは reduce でも動く。 由紀精密も CSS に 0 で、reduce でもトップの写真が10秒ごとに差し替わる。
10. SP 用の画像の出し分けが崩れて、SP で PC と同じ量を読む（Valmont：SP＝PC の画像、竹中庭園緑化：pcOnly と spOnly の img を両方の幅で読む、HILLTOP：`<video>` の source を後から JS で消すので SP でも PC 用 60.7MB の動画）。動画は JS で src を1つだけ入れてから load() する。`<picture>` の source で出し分ける。 由紀精密の事業ページも SP＝PC の 7.40MB（スライダー4枚 4.3MB）。
11. ニュースの絞り込みはページごと読み直す作りで、1回に1MB 前後増える（LayerX：SP で最大 +1.3MB、竹中庭園緑化：PC 2.8〜3.3s・+0.9〜2.0MB）。絞り込みは URL に残したまま、その場で一覧だけ替える（Mistral AI は 92件を全部持ち、57〜70ms・通信 0KB で替え、URL に ?categories=a,b&search=x を残した）。日清食品グループも会社・年・月を選ぶたびに読み直し（+0.5〜2.3MB・2.3〜4.9秒）、件数も出ない。Life at Spotify の /jobs も、選ぶと URL（?l=london&c=…&q=…）に残したまま、1回 15〜16KB の JSON で一覧だけ替える（読み直しても残る）。 由紀精密もニュースのカテゴリは読み直し（2.1s・+106KB）、年の select は onChange で即移動（+537KB）。一方で同じサイトの事例の絞り込みは手元の36件を 0KB で替え、#material08 を URL に残す。
12. 画像の alt を手で書くと、画面と食い違う（Valmont：事業・採用の画像に alt 無し、竹中庭園緑化：SVG 見出しの alt が3か所違う、HILLTOP：社員3人の写真の alt が全部「開発エンジニア」）。alt は画面に出ている名前・見出しのデータから作る。日清食品グループの総合採用サイトでは、画面で「埼玉工場採用」「神戸工場採用」の2枚の alt が両方「東日本明星」。Life at Spotify のトップは img 31のうち 21に alt 属性が無い。
13. 色の札・帯の上の白字が 4.5:1 に届かない（竹中庭園緑化：#7a9f9f で 2.88:1、HILLTOP：職種札 #da338a で 4.36:1・縦の札 2.75:1・Join Us! の帯の中央 2.94:1）。札の地は白で 4.5 を超える濃さに決め、グラデーションの上には小さな白字を置かない。日清食品グループは白字／#ff0000 の NEW・検索のボタンで 4.00:1、#ff0000 の文字も白地で 4.00:1。 由紀精密：フッターの白／#b2b2b2 で 2.12:1、確認ボタンの白／#e63232 で 4.31:1。
14. 採用ページに募集の件数が出ない。外の採用システムへ「応募」のボタンで渡すだけになる（Valmont：Workday と LinkedIn へ下線リンク3つ、Mistral AI：Apply now 2つで Ashby へ、Ashby には 226件）。作るときは班・職種ごとの件数と勤務地を採用ページに出し、日付を添える。逆に件数を出したのは Life at Spotify：SP のメニューの緑の帯「All Jobs 79」、場所の選択肢「London (41)」、一覧の上の「79 jobs in all locations…」、SP のシートの「See 79 jobs」。
15. トップの h1 が1つになっていない（HILLTOP：6つ、Mistral AI：0で最初の1文は aria-hidden）。最初の画面の「何の会社か」の1文を、ただ1つの h1 にする。日清食品グループのトップの h1 は CM の題「「カプポッポ 篇」」で、title は「商品情報｜…」。Life at Spotify のトップの h1「Join the band」は約5秒で visibility:hidden になり、募集の一覧 /jobs には h1 が無い（見出しの文は input の value）。 由紀精密は全5ページで h1 がロゴの画像（alt「YUKI」）で、トップの1文は p、ページ名は h2。
16. 解析タグと同意の窓が全ページに乗り、軽いページほど比率が大きい（Mistral AI：同意の窓 axept.io 1,445KB＋GTM 1,014KB で、トップの画像 863KB より重い。日清食品グループ：GTM 2本 1,668KB を全ページで読み、グループ会社のページ 4,050KB の 41%）。作るときはタグ管理を1本にまとめ、ページの重さの上限にタグも数える。Life at Spotify の /jobs も GTM 933KB＋OneTrust 763KB で、ページ自身 3,042KB の 56%。 由紀精密も GTM 921KB を全ページで読み、お知らせ（2,030KB）の 31%。
17. 募集の詳細に JobPosting の構造化データが無く、Organization も無い（HILLTOP：JSON-LD 0、Life at Spotify：全ページ 0）。作るときは募集の詳細ごとに JobPosting（職種・勤務地・雇用形態・掲載日・給与の下限）を入れる。 由紀精密も JobPosting は無い（Organization は Yoast で入る）。
18. ニュースや募集の日付が、年が無いか、日付そのものが無い（HILLTOP：職場の数字に日付なし、Life at Spotify：Latest の 40個の日付すべてに年が無く「October 13」が2回）。日付は年月日で書き、<time datetime> にする。
